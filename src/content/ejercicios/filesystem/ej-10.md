  Como en la resolución de la cátedra, **las syscalls sobre archivos no son bloqueantes** (`open`,

    justificacion: |
      Los cerrojos son **sugeridos** (el SO solo los aplica entre los procesos que los piden) y
      **compartidos** (varios lectores a la vez, un solo escritor).

      1. **P1** abre para leer, toma el lock **compartido**, lee e imprime **`B`**. El clock lo
         manda a Ready **con el lock tomado**. Bloqueados: ninguno.
      2. **P2** abrió para escribir y pide el lock **exclusivo**: P1 tiene uno compartido, así que
         **P2 se bloquea** en `lock`. No imprime nada.
      3. **P3** pide el lock compartido: es compatible con el de P1, lo obtiene e imprime **`B`**.
         Bloqueados: P2.
      4. **P4** hace `read` **sin** pedir el lock. Como el cerrojo es **sugerido**, el SO no lo
         controla: la lectura funciona e imprime **`B`**. Bloqueados: P2.
      5. P1 y P3 hacen `unlock`. Sin lectores, **P2** obtiene el lock exclusivo, escribe `A`, lo
         lee e imprime **`A`**.

      Salida: **P1: B · P3: B · P4: B · P2: A**.

      Es el ejercicio 9 con locks **obligatorios** cambiados por **sugeridos**: lo único que cambia
      es P4. Con el obligatorio su `read` sin lock falla e imprime `-`; con el sugerido lee el
      archivo.

    opciones:
      - texto: 'Nada: P4 lee igual porque nunca pidió el lock'

    justificacion: |
      Un lock **sugerido** solo coordina a los procesos que lo usan: P4 no lo pide y el SO lo deja
      leer. Con uno **obligatorio** el SO valida cada operación: el `read` de P4 se rechaza y, como
      las syscalls no son bloqueantes, devuelve error sin dormir a P4. Imprime el valor inicial de
      `var`, `'-'`. Es exactamente el ejercicio 9.

      El resto no cambia: P1 y P3 comparten el lock de lectura y P2 espera el exclusivo hasta que
      los dos lo liberan.

En un sistema donde se utiliza el algoritmo de corto plazo RR, se dispone de una serie de procesos
que operan sobre un mismo archivo. Los mismos se encuentran en Ready en orden 1, 2, 3 y 4.

<div class="codigo-columnas">

**Proceso 1**

```c
open(f, read)
var = '-'
lock(f)
read(f, var)
print(var)
unlock(f)
```

**Proceso 2**

```c
open(f, write)
var = 'A'
lock(f)
write(f, var)
read(f, var)
print(var)
unlock(f)
```

**Proceso 3**

```c
open(f, read)
var = '-'
lock(f)
read(f, var)
print(var)
unlock(f)
```

**Proceso 4**

```c
open(f, read)
var = '-'
read(f, var)
print(var)
```

</div>

**Indique ordenadamente qué valores serán impresos por pantalla**, indicando para cada impresión:
qué proceso imprime, el valor, y la lista de procesos bloqueados por el cerrojo.

Notas:

- Los cerrojos usados son de tipo **sugerido y compartido**, a través de las syscalls lock/unlock.
- El archivo contiene un solo byte: `'B'` y todas las operaciones sobre el mismo ocurren sobre el
  primer byte.
- Todos los procesos recibirán una interrupción de clock luego de ejecutar su sentencia `print()`.
- Las syscalls lock/unlock están configuradas como **bloqueantes**, pero el resto se comportan como
  **no bloqueantes**.
