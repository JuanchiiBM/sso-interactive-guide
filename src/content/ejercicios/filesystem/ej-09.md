nota: |
  Como en la resolución de la cátedra, suponé que **las syscalls sobre archivos no son bloqueantes**
  (`open`, `read`, `write`): si el SO no puede hacerlas, devuelven error y el proceso sigue. Las
  únicas que pueden bloquear al proceso son las del cerrojo (`lock`).

  `lock(f)` toma el cerrojo según el modo de apertura: **compartido** si el archivo se abrió para
  leer, **exclusivo** si se abrió para escribir.

        - ['2.ª', { respuesta: P3, texto: true, alternativas: ['3'] }, { respuesta: A, texto: true }, { respuesta: P2, texto: true, alternativas: ['2'] }]
        - ['3.ª', { respuesta: P4, texto: true, alternativas: ['4'] }, { respuesta: '-', texto: true, alternativas: ["'-'"] }, { respuesta: P2, texto: true, alternativas: ['2'] }]
        - ['4.ª', { respuesta: P2, texto: true, alternativas: ['2'] }, { respuesta: B, texto: true }, { respuesta: '—', texto: true, alternativas: ['-', ninguno, vacia, vacía] }]
    justificacion: |
      Los cerrojos son **obligatorios** (el SO los hace cumplir aunque el proceso no los pida) y
      **compartidos** (varios lectores a la vez, un solo escritor).

      1. **P1** abre para leer, toma el lock **compartido**, lee e imprime **`A`**. El clock lo
         manda a Ready **con el lock tomado**. Bloqueados: ninguno.
      2. **P2** abrió para escribir y pide el lock **exclusivo**: P1 tiene uno compartido, así que
         **P2 se bloquea** en `lock`. No imprime nada.
      3. **P3** pide el lock compartido: es compatible con el de P1, lo obtiene e imprime **`A`**.
         Bloqueados: P2.
      4. **P4** hace `read` **sin** pedir el lock. Como el cerrojo es obligatorio, el SO rechaza la
         lectura: la syscall **falla** (no bloquea) y `var` sigue valiendo `'-'`. Imprime **`-`**.
         Bloqueados: P2.
      5. P1 y P3 hacen `unlock`. Sin lectores, **P2** obtiene el lock exclusivo, escribe `B`, lo
         lee e imprime **`B`**.

      Salida: **P1: A · P3: A · P4: - · P2: B**.

      El ejercicio 10 es el mismo código con locks **sugeridos**: ahí P4 sí puede leer.
preguntas:
  - enunciado: '¿Por qué P4 imprime `-` y no `A`?'
    opciones:
      - texto: 'Porque P4 se bloquea esperando el lock y, al volver, el archivo ya dice `B`'
        explicacion: 'P4 nunca pide el lock, y con syscalls no bloqueantes no espera: falla.'
      - texto: 'Porque el lock es obligatorio: el SO rechaza su `read` sin lock'
        explicacion: Correcta.
      - texto: 'Porque P2 ya escribió `B` y P4 lee un valor a medio escribir'
        explicacion: 'P2 está bloqueado en `lock`: todavía no escribió nada.'
      - texto: 'Porque un lock compartido no admite más de dos lectores a la vez'
        explicacion: 'Un lock compartido admite cualquier cantidad de lectores.'
    correcta: 1
    justificacion: |
      Con un lock **obligatorio** el SO controla cada operación sobre el archivo. Mientras P1 y P3
      tienen el cerrojo, P4 intenta leer **sin haberlo pedido**: el SO no se lo permite. Como las
      syscalls sobre archivos son **no bloqueantes**, la lectura devuelve un error en lugar de
      dormir a P4, y `var` conserva su valor inicial `'-'`.

      Si el lock fuera **sugerido** (ejercicio 10), el SO no controla a quien no lo pide y P4 leería
      el contenido real del archivo.

En un sistema donde se utiliza el algoritmo de corto plazo RR, se dispone de una serie de procesos
que operan sobre un mismo archivo. Los mismos se encuentran en Ready en orden 1, 2, 3 y 4.

<div class="codigo-columnas">

**Proceso 1**

```c
open(f, read)
var = '-'
lock(f)
read(f, var)
print(var)
unlock(f)
```

**Proceso 2**

```c
open(f, write)
var = 'B'
lock(f)
write(f, var)
read(f, var)
print(var)
unlock(f)
```

**Proceso 3**

```c
open(f, read)
var = '-'
lock(f)
read(f, var)
print(var)
unlock(f)
```

**Proceso 4**

```c
open(f, read)
var = '-'
read(f, var)
print(var)
```

</div>

**Indique ordenadamente qué valores serán impresos por pantalla**, indicando para cada impresión:
qué proceso imprime, el valor, y la lista de procesos bloqueados por el cerrojo.

Notas:

- Los cerrojos usados son de tipo **obligatorio y compartido**, a través de las syscalls
  lock/unlock.
- El archivo contiene un solo byte: `'A'` y todas las operaciones sobre el mismo ocurren sobre el
  primer byte.
- Todos los procesos recibirán una interrupción de clock luego de ejecutar su sentencia `print()`.
