preguntas:
  - enunciado: 'a) ¿Qué caracteriza a un lock obligatorio?'
    opciones:
      - texto: 'Los procesos tienen que pedirlo, y el que no lo pide accede igual'
        explicacion: 'Eso es un lock sugerido.'
      - texto: 'El SO lo hace cumplir: frena el acceso incompatible aunque el proceso no pida el lock'
        explicacion: 'Correcta: a cambio, el SO valida cada acceso (más overhead).'
      - texto: 'Es obligatorio pedirlo antes de abrir cualquier archivo del sistema, o el open de ese archivo falla'
        explicacion: 'No aplica a todos los archivos: es el tipo de lock que tiene un archivo.'
    correcta: 1
    justificacion: |
      Un lock **obligatorio** (*mandatory*) lo impone el **SO**: lo registra en la tabla global de
      archivos abiertos y lo controla en cada `open`, `read` o `write`. Un acceso incompatible no se
      realiza: la syscall **devuelve un error** o **bloquea** al proceso hasta que se libere el lock.

      El proceso que no pidió el lock no lo puede saltear (1C2025 TT: un proceso que lee sin tomar el
      lock obligatorio recibe un error). La contra es el **overhead** de validar cada acceso.
  - enunciado: 'b) Con un lock obligatorio, ¿qué diferencia hay entre uno exclusivo y uno compartido?'
    opciones:
      - texto: 'El exclusivo lo fuerza el SO y el compartido lo tienen que respetar los procesos'
        explicacion: 'Quién lo fuerza es la otra clasificación: acá los dos son obligatorios.'
      - texto: 'Exclusivo: el SO deja un solo proceso · Compartido: deja varios lectores'
        explicacion: 'Correcta: escribir sigue siendo de a uno en los dos.'
      - texto: 'El compartido deja escribir a varios procesos a la vez, si escriben bytes distintos'
        explicacion: 'Lo de porciones de bytes vale para cualquier lock; el compartido comparte solo lecturas.'
    correcta: 1
    justificacion: |
      | Lock obligatorio | P1 tiene el archivo | P2 quiere leer | P2 quiere escribir |
      | --- | --- | --- | --- |
      | **Exclusivo** | para leer o escribir | el SO lo frena | el SO lo frena |
      | **Compartido** | para leer | **puede** | el SO lo frena |
      | **Compartido** | para escribir | el SO lo frena | el SO lo frena |

      "El SO lo frena" es que la syscall de P2 falla o lo bloquea hasta que P1 libere el lock.
