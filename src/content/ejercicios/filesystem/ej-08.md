preguntas:
  - enunciado: 'a) ¿Qué ocurre si un proceso P2 intenta abrirlo para escritura?'
    opciones:
      - texto: 'El SO rechaza el open de P2 con un error, porque el archivo tiene un lock exclusivo tomado'
        explicacion: 'El SO no hace cumplir un lock sugerido: no rechaza el open.'
      - texto: 'Si P2 pide el lock, espera a que P1 lo libere; si no lo pide, escribe igual'
        explicacion: 'Correcta: el lock solo frena a los procesos que lo piden.'
      - texto: 'P2 escribe sin esperar, porque P1 solo está leyendo'
        explicacion: 'Si P2 pide el lock, el exclusivo lo hace esperar aunque P1 solo lea.'
      - texto: 'Si P2 pide el lock, lo comparte con P1 y escriben a la vez'
        explicacion: 'Un lock exclusivo no se comparte con nadie.'
    correcta: 1
    justificacion: |
      Hay que separar las dos clasificaciones:

      - **Exclusivo:** mientras P1 lo tenga, ningún otro proceso puede tomarlo, sea para leer o para
        escribir. Si P2 pide el lock, **queda bloqueado** hasta que P1 haga `unlock` (o reciba un
        error, si la syscall no es bloqueante).
      - **Sugerido:** el SO no valida los accesos. Si P2 **no** pide el lock, el `open` y el `write`
        funcionan, y P1 puede leer datos a medio escribir. Respetar el lock es responsabilidad del
        programador.
  - enunciado: 'b) ¿Qué ocurre si un proceso P2 intenta abrirlo para lectura?'
    opciones:
      - texto: 'Si P2 pide el lock, lo comparte con P1: dos lectores no se molestan'
        explicacion: 'Eso pasaría con uno compartido; el exclusivo no se comparte ni entre lectores.'
      - texto: 'El SO rechaza el open de P2, aunque P2 no pida el lock, porque ya hay un lector'
        explicacion: 'Un lock sugerido no frena a quien no lo pide.'
      - texto: 'Si P2 pide el lock, espera a que P1 lo libere; si no lo pide, lee igual'
        explicacion: 'Correcta: el exclusivo frena también a los lectores, pero solo a los que lo piden.'
    correcta: 2
    justificacion: |
      Igual que en a): el **exclusivo** no mira el modo, así que P2 queda bloqueado al pedir el lock
      aunque solo quiera leer. Y como es **sugerido**, si P2 no lo pide lee sin esperar (en este
      caso sin riesgo, porque nadie está escribiendo).
  - enunciado: 'c) ¿Hubieran cambiado sus respuestas si P1 lo hubiese abierto en modo escritura?'
    opciones:
      - texto: 'Sí: con P1 escribiendo, el SO pasa a frenar a P2 aunque P2 no pida el lock'
        explicacion: 'El modo de apertura no vuelve obligatorio a un lock sugerido.'
      - texto: 'No: el exclusivo no mira el modo, y un sugerido no frena a quien no lo pide'
        explicacion: 'Correcta: a) y b) quedan igual.'
      - texto: 'Sí: P2 podría tomar el lock para leer, porque el exclusivo solo aplica al que escribe'
        explicacion: 'El exclusivo aplica a cualquier modo.'
    correcta: 1
    justificacion: |
      Las respuestas no cambian:

      - El lock **exclusivo** ya bloqueaba a cualquier P2 que lo pidiera, para leer o para escribir:
        que P1 escriba no agrega restricciones.
      - El lock sigue siendo **sugerido**: un P2 que no lo pide accede igual. La diferencia es el
        riesgo: ahora P2 puede leer datos a medio escribir o pisar lo que escribe P1.
---

Suponga que existe un archivo `/datos/informe.txt`, el cual fue abierto por un proceso (P1) en modo
**lectura**. Sabiendo que el lock utilizado es de tipo **sugerido exclusivo**, responda:

- a) ¿Qué ocurre si un proceso P2 intenta abrirlo para escritura?
- b) ¿Qué ocurre si un proceso P2 intenta abrirlo para lectura?
- c) ¿Hubieran cambiado sus respuestas si P1 lo hubiese abierto en modo **escritura**?

> **Nota:** se asume que P1 tomó el lock al abrir el archivo.
