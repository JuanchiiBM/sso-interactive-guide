preguntas:
  - enunciado: 'a) ¿Qué caracteriza a un lock sugerido?'
    opciones:
      - texto: 'El SO lo toma solo al abrir el archivo y valida cada lectura y escritura'
        explicacion: 'Eso es un lock obligatorio.'
      - texto: 'Lo piden los procesos; el SO no frena a quien no lo pide'
        explicacion: 'Correcta: funciona solo si todos los procesos respetan el protocolo.'
      - texto: 'Solo sirve para lectura: para escribir hace falta uno obligatorio'
        explicacion: 'Sugerido u obligatorio es quién lo impone, no para qué operación es.'
      - texto: 'El SO lo sugiere al usuario con un aviso antes de modificar el archivo'
        explicacion: '"Sugerido" quiere decir que su cumplimiento queda en manos de los procesos.'
    correcta: 1
    justificacion: |
      Un lock **sugerido** (*advisory*) lo piden los procesos con `lock` / `unlock`. El SO registra
      quién lo tiene y bloquea a otro proceso que **también lo pida**, pero no valida los accesos: un
      proceso que hace `read` o `write` **sin** pedir el lock accede igual. La consistencia queda en
      manos del programador.

      Ventaja: **menos overhead**, porque el SO no tiene que validar cada acceso al archivo.
  - enunciado: 'b) Entre procesos que piden el lock sugerido, ¿qué diferencia hay entre uno exclusivo y uno compartido?'
    opciones:
      - texto: 'Exclusivo: un proceso a la vez · Compartido: varios lectores a la vez'
        explicacion: 'Correcta: para escribir, el compartido también es de a uno.'
      - texto: 'El exclusivo deja leer a varios y el compartido deja escribir a varios'
        explicacion: 'Ninguno deja escribir a dos procesos a la vez.'
      - texto: 'El exclusivo toma el archivo entero y el compartido solo una porción de bytes'
        explicacion: 'Los dos pueden tomar el archivo entero o una porción: la diferencia es cuántos procesos lo comparten.'
      - texto: 'No hay diferencia, porque al ser sugerido el SO no los distingue'
        explicacion: 'El SO sí bloquea a quien pide un lock incompatible; lo que no hace es frenar a quien no lo pide.'
    correcta: 0
    justificacion: |
      | Lock | P1 lo tiene | Otro proceso que **pide** el lock para leer | … para escribir |
      | --- | --- | --- | --- |
      | **Exclusivo** | para leer o escribir | espera | espera |
      | **Compartido** | para leer | entra (comparten) | espera |
      | **Compartido** | para escribir | espera | espera |

      El exclusivo funciona como un **mutex**; el compartido, como el problema de lectores y
      escritores. En los dos casos, al ser sugerido, un proceso que **no** pide el lock lee o escribe
      sin esperar.
