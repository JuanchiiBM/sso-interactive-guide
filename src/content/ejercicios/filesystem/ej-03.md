preguntas:
  - enunciado: 'a) ¿Qué ocurre si un proceso P2 intenta abrirlo para escritura?'
    opciones:
      - texto: 'Si P2 pide el lock, lo comparte con P1 y escribe mientras P1 lee'
        explicacion: 'El compartido se comparte solo entre lectores: escribir es de a uno.'
      - texto: 'Si P2 pide el lock, espera a que P1 lo libere; si no lo pide, escribe igual'
        explicacion: 'Correcta: escribir requiere el lock para P2 solo, y un sugerido no frena a quien no lo pide.'
      - texto: 'El SO rechaza el open de P2 con un error, aunque P2 no haya pedido ningún lock'
        explicacion: 'El SO no hace cumplir un lock sugerido.'
    correcta: 1
    justificacion: |
      - **Compartido:** varios procesos pueden tenerlo **para leer**; para escribir hace falta tenerlo
        solo. Si P2 pide el lock para escribir, **queda bloqueado** hasta que P1 (y cualquier otro
        lector) lo libere.
      - **Sugerido:** si P2 no pide el lock, el SO lo deja abrir y escribir igual.

      Es el caso de la resolución del 1R 2C2025: el proceso que pide el lock para escribir queda en
      la lista de bloqueados hasta que los dos lectores liberan, mientras que el que lee sin pedir el
      lock lee sin esperar.
  - enunciado: 'b) ¿Qué ocurre si un proceso P2 intenta abrirlo para lectura?'
    opciones:
      - texto: 'Lee: si pide el lock lo comparte con P1, y si no lo pide tampoco se lo impiden'
        explicacion: 'Correcta: dos lectores son compatibles.'
      - texto: 'Si P2 pide el lock, espera a que P1 lo libere; si no lo pide, lee igual'
        explicacion: 'Eso pasaría con uno exclusivo: el compartido admite varios lectores.'
      - texto: 'El SO bloquea a P2 hasta que P1 cierre el archivo, haya pedido el lock o no lo haya pedido'
        explicacion: 'Un lock sugerido no frena a quien no lo pide, y uno compartido no frena a otro lector.'
    correcta: 0
    justificacion: |
      Es justamente para lo que existe el lock **compartido**: P1 y P2 leen a la vez, los dos con el
      lock tomado, y ninguno espera. Si P2 no pidiera el lock, como es **sugerido**, también leería.
  - enunciado: 'c) ¿Hubieran cambiado sus respuestas si P1 lo hubiese abierto en modo escritura?'
    opciones:
      - texto: 'No: mientras el lock sea sugerido, el compartido deja entrar a todos los procesos que lo pidan'
        explicacion: 'Con P1 escribiendo, el lock compartido ya no admite a otro proceso que lo pida.'
      - texto: 'Sí, cambia a): ahora P2 podría escribir junto con P1'
        explicacion: 'Dos escritores nunca comparten el lock.'
      - texto: 'Sí, cambia b): P2 que pide el lock para leer espera a que P1 termine de escribir'
        explicacion: 'Correcta: a) queda igual.'
    correcta: 2
    justificacion: |
      Con P1 **escribiendo**, el lock no se comparte con nadie:

      | P2 pide el lock para… | P1 lee | P1 escribe |
      | --- | --- | --- |
      | escribir | espera | espera |
      | leer | **entra** | **espera** |

      Cambia b): P2 ya no puede compartir el lock y queda bloqueado. a) no cambia. Y sigue valiendo
      lo del lock **sugerido**: un P2 que no pide el lock lee o escribe igual, ahora con el riesgo de
      ver datos a medio escribir.

Suponga que existe un archivo `/datos/informe.txt`, el cual fue abierto por un proceso (P1) en modo
**lectura**. Sabiendo que el lock utilizado es de tipo **sugerido compartido**, responda:

- a) ¿Qué ocurre si un proceso P2 intenta abrirlo para escritura?
- b) ¿Qué ocurre si un proceso P2 intenta abrirlo para lectura?
- c) ¿Hubieran cambiado sus respuestas si P1 lo hubiese abierto en modo **escritura**?

> **Nota:** se asume que P1 tomó el lock al abrir el archivo.
