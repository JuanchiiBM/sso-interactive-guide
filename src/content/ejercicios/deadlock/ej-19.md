En un sistema que utiliza **detección y recuperación de deadlock**, ejecutan dos KLT. El algoritmo de planificación utilizado por el sistema operativo es **RR Q = 3**. El algoritmo de detección y recuperación, que ejecuta como un **proceso más**, se bloquea luego de ejecutar por 5 unidades de tiempo para volver a ejecutar según la planificación. Además, soluciona el deadlock **finalizando procesos con mayor tiempo restante** de ejecución.

Grafique el diagrama correspondiente a la traza de ejecución **hasta el instante 25** e indique en qué instante finalizó cada KLT.

|                   | KLTA | KLTB | Detector de deadlock |
| ----------------- | ---- | ---- | -------------------- |
| Tiempo de llegada | 1    | 2    | 0                    |

<div class="codigo-columnas">

**KLTA**

```c
get(recurso_A)
a++
get(recurso_B)
b=a+b
d=b*2
release(recurso_B)
release(recurso_A)
print(d)
```

**KLTB**

```c
get(recurso_B)
b++
get(recurso_A)
b=a+b
release(recurso_A)
release(recurso_B)
```

**Detector de deadlock**

```c
while(true) {
  deadlock_detect()
  sleep(5 ut)
}
```

</div>

**Costos:** `a` y `b` variables globales; `d` variable local; `deadlock_detect()`: 2 u.t.; `get(recurso)`: 2 u.t.; `release(recurso)`: 1 u.t.; `sleep(n)`: 0 u.t. (bloquea n); operaciones con variables: 1 u.t.; `print()`: 2 u.t.

**Nota:** `get(recurso)` es bloqueante si el recurso no está disponible. Los recursos A y B tienen una sola instancia cada uno.
