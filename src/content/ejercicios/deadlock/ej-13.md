- enunciado: a) ¿Cómo podrían quedar en deadlock?
  opciones:
  - texto: P1 obtiene R1, P2 obtiene R2, y cada uno pide el del otro
    explicacion: Correcta.
  - texto: Un proceso pide dos veces el mismo recurso y se bloquea solo
    explicacion: 'Podría pasar, pero no es un deadlock entre procesos: es un proceso esperándose a sí
      mismo.'
  - texto: 'No pueden: devolver_recursos libera todo al final de cada vuelta'
    explicacion: Si quedan bloqueados en el segundo get_resource, nunca llegan a devolver.
  - texto: 'Solo si hay más procesos que recursos disponibles en el sistema'
    explicacion: Con dos procesos y dos recursos ya alcanza.
  correcta: 0
  justificacion: |
    | Proceso 1 | Proceso 2 |
    | --------- | --------- |
    | `recurso1 = get_resource()` → R1 | |
    | | `recurso1 = get_resource()` → R2 |
    | `recurso2 = get_resource()` → R2: **se bloquea** | |
    | | `recurso2 = get_resource()` → R1: **se bloquea** |

    Cada uno retiene un recurso y espera el que tiene el otro: **espera circular**, con recursos de una
    sola instancia y sin desalojo.
- enunciado: b) ¿Cómo prevenirlo sin usar semáforos?
  opciones:
  - texto: Que get_resource() devuelva recursos distintos pero al azar
    explicacion: 'Distintos no alcanza: el orden cruzado sigue siendo posible.'
  - texto: Hacer que cada proceso libere el recurso antes de usarlo
    explicacion: Entonces no lo tendría al usarlo.
  - texto: Aumentar la cantidad de procesos
    explicacion: Más procesos compitiendo solo hace más probable la espera circular.
  - texto: Que get_resource() entregue los recursos en un orden fijo
    explicacion: Correcta.
  correcta: 3
  justificacion: |
    De las cuatro condiciones necesarias (mutua exclusión, retención y espera, sin desalojo, espera
    circular), la más fácil de romper acá es la **espera circular**: si `get_resource()` devuelve los
    recursos **ordenados** (siempre el de menor número primero), nunca puede haber un ciclo. Es
    **prevención** por orden de pedido.
---

Se encuentran N procesos compartiendo distintos recursos, de los cuales existe **una sola instancia** de cada uno, ejecutando el siguiente pseudocódigo:

```c
while(true){
    t_rec recurso1 = get_resource(); // devuelve aleatoriamente un recurso compartido, bloqueante si no está disponible
    t_rec recurso2 = get_resource();
    usar_recursos();
    devolver_recursos();
}
```

a) Demuestre que dichos procesos podrían quedar en deadlock.

b) Considere las condiciones necesarias y suficientes para la existencia de deadlock y proponga una solución para prevenirlo sin usar semáforos.
