preguntas:
- enunciado: ¿Qué procesos forman parte del deadlock?
  opciones:
  - texto: 'Todos: ninguno de los cinco avanza'
    explicacion: 'No avanzar no alcanza: hay que estar en la espera circular.'
  - texto: P1 y P2
    explicacion: Correcta.
  - texto: P1, P2 y P4, porque P4 espera mutex_a
    explicacion: 'P4 espera, pero no retiene nada: no cierra ningún ciclo.'
  - texto: 'Ninguno: mutex_c está libre'
    explicacion: 'mutex_c no lo espera nadie: no destraba el ciclo.'
  correcta: 1
  justificacion: |
    Un valor negativo en un mutex indica cuántos procesos están bloqueados en él. Con las asignaciones:

    ```grafo
    procesos: P1, P2, P3, P4, P5
    recursos: A, B, C, D
    B -> P1
    C -> P1
    A -> P2
    D -> P2
    P1 -> A
    P4 -> A
    P2 -> B
    P3 -> D
    P5 -> D
    resaltar-ciclo
    ```

    El ciclo es `P1 → A → P2 → B → P1`: P1 retiene B y espera A; P2 retiene A y espera B. **P1 y P2
    están en deadlock.**
- enunciado: ¿Qué les pasa a P3, P4 y P5?
  opciones:
  - texto: Están en deadlock, porque esperan recursos del ciclo
    explicacion: 'No retienen ningún recurso: no forman parte de la espera circular.'
  - texto: Hacen espera activa sobre sus mutex
    explicacion: 'Un wait bloquea al proceso: no consume CPU mientras espera.'
  - texto: Van a avanzar apenas se libere mutex_c
    explicacion: Nadie espera mutex_c.
  - texto: Quedan bloqueados para siempre sin estar en el deadlock
    explicacion: Correcta.
  correcta: 3
  justificacion: |
    P4 espera `mutex_a` y P3 y P5 esperan `mutex_d`, que retiene P2 (en deadlock). Nunca los van a
    conseguir, pero **no retienen recursos**: no cierran ningún ciclo. La resolución lo llama
    **inanición** (starvation): quedan bloqueados indefinidamente por culpa del deadlock de otros.
---

En un sistema ejecutan concurrentemente cinco procesos con semáforos mutex compartidos. Se sospecha que se produjo algún tipo de interbloqueo, ya que ninguno de ellos avanza. Dado el estado de los semáforos y procesos:

```c
mutex_a { valor = -2  blocked -> [P1, P4] }
mutex_b { valor = -1  blocked -> [P2] }
mutex_c { valor =  0  blocked -> [] }
mutex_d { valor = -2  blocked -> [P3, P5] }

Asignaciones:
P1 -> [mutex_b, mutex_c]
P2 -> [mutex_a, mutex_d]
P3, P4 y P5 sin semáforos asignados
```

Realice el grafo de asignación de recursos e indique qué procesos forman parte del deadlock.
