preguntas:
  - enunciado: 'a) ¿Se produce algún deadlock en este estado?'
    opciones:
      - texto: 'Sí: el grafo tiene un ciclo y todos los recursos del ciclo tienen una única instancia'
        explicacion: 'Correcta: ciclo P1 → R2 → P2 → R1 → P1 con recursos de una instancia implica deadlock.'
      - texto: 'Puede o no haber deadlock: hay un ciclo, pero habría que correr el algoritmo de detección'
        explicacion: 'Esa duda aplica cuando hay recursos con varias instancias; acá todos tienen una sola.'
      - texto: 'No, porque P3 puede terminar y liberar R3, y eso destraba al resto'
        explicacion: 'R3 no lo pide nadie: que P3 lo libere no ayuda a P1 ni a P2.'
      - texto: 'No, porque no todos los procesos están esperando recursos'
        explicacion: 'El deadlock no exige que todo el sistema esté trabado, alcanza con un subconjunto de procesos.'
    correcta: 0
    justificacion: |
      Armando el grafo con las relaciones del enunciado:

      ```grafo
      procesos: P1, P2, P3
      recursos: R1, R2, R3
      R1 -> P1
      P1 -> R2
      R2 -> P2
      P2 -> R1
      R3 -> P3
      resaltar-ciclo
      ```

      Se ve un **ciclo**: `P1 → R2 → P2 → R1 → P1`. Como **todos los recursos del ciclo tienen una única instancia**, el ciclo es condición suficiente: **hay deadlock**.

      Verificando las condiciones de Coffman para P1 y P2:

      1. **Mutua exclusión**: R1 y R2 tienen una sola instancia y solo los usa un proceso a la vez.
      2. **Retención y espera**: P1 retiene R1 mientras espera R2, y P2 retiene R2 mientras espera R1.
      3. **Sin desalojo**: nada indica que el SO pueda quitarles los recursos.
      4. **Espera circular**: P1 espera a P2 y P2 espera a P1.

      Se cumplen las cuatro, así que el deadlock es seguro.

      Por qué las otras opciones no van:

      - **"Puede o no haber"**: es la regla para ciclos con recursos de **varias** instancias, donde otra instancia podría liberarse por fuera del ciclo. Con una sola instancia no hay escapatoria.
      - **"P3 destraba al resto"**: P3 termina y libera R3, pero ni P1 ni P2 lo piden, así que no cambia nada para ellos.
      - **"No todos esperan"**: el deadlock se define sobre un **conjunto** de procesos. Que otros procesos del sistema sigan avanzando no lo evita.
  - enunciado: 'b) ¿Qué procesos y qué recursos involucra el deadlock, y qué pasa con P3?'
    opciones:
      - texto: 'P1, P2 y P3 con R1, R2 y R3: P3 retiene R3 y todo el sistema queda trabado'
        explicacion: 'P3 no solicita nada y puede terminar: no forma parte del ciclo.'
      - texto: 'P1 y P2 con R1, R2 y R3: R3 queda retenido por P3 y forma parte de la espera'
        explicacion: 'R3 no está en el ciclo; que esté ocupado un rato no lo hace parte del deadlock.'
      - texto: 'Solo P1 con R1 y R2: es el que inicia la espera y P2 puede terminar después'
        explicacion: 'El deadlock necesita al menos dos procesos esperándose mutuamente; P2 también está trabado.'
      - texto: 'P1 y P2 con R1 y R2; P3 no participa del ciclo y termina liberando R3'
        explicacion: 'Correcta: el ciclo solo pasa por P1, P2, R1 y R2.'
    correcta: 3
    justificacion: |
      El deadlock abarca exactamente a los procesos y recursos que forman el ciclo:

      - **Procesos**: P1 y P2.
      - **Recursos**: R1 (asignado a P1, pedido por P2) y R2 (asignado a P2, pedido por P1).

      **P3** tiene asignado R3 y no solicita ningún otro recurso. No está esperando nada, así que no participa de ninguna espera circular. Ejecuta, **finaliza normalmente y libera R3**.

      Después de que P3 termina, el estado de P1 y P2 no cambia: ninguno de los dos pide R3, así que siguen bloqueados para siempre. Sin intervención externa (por ejemplo, matar a uno de los dos o expropiarle su recurso), el deadlock no se rompe.

      Errores típicos que representan los distractores:

      - Pensar que un deadlock "congela" a todo el sistema. Solo afecta al conjunto de procesos que se esperan entre sí.
      - Incluir recursos que están ocupados pero fuera del ciclo, como R3.
      - Creer que un solo proceso puede estar en deadlock consigo mismo en este escenario, cuando la espera circular necesita la cadena P1 ↔ P2.

Se tienen tres procesos P1, P2 y P3 y tres recursos R1, R2 y R3, todos con una única instancia.
El estado es:

- R1 → P1
- P1 → R2
- R2 → P2
- P2 → R1
- R3 → P3

P3 no solicita ningún otro recurso y puede finalizar normalmente.
Realiza el grafo e indica si se produce algún deadlock. En caso afirmativo, ¿qué proceso y qué recursos involucra? En caso contrario, indica cómo van finalizando los procesos.
