preguntas:
- enunciado: a) ¿Podría generarse deadlock si se ejecutaran únicamente los procesos 2 y 3?
  opciones:
  - texto: 'Sí: P2 toma A, P3 toma B, y se esperan'
    explicacion: P3 no puede tomar B sin haber tomado A antes.
  - texto: 'No: los dos piden en el mismo orden, sin espera circular'
    explicacion: Correcta.
  - texto: 'Sí: los dos piden C y hay una sola instancia'
    explicacion: 'Competir por un recurso no alcanza: hace falta una espera circular.'
  - texto: No, porque liberan todos los recursos juntos al final
    explicacion: Liberar juntos no evita el deadlock; lo evita el orden de pedido.
  correcta: 1
  justificacion: |
    P2 pide A → C y P3 pide A → B → C: los dos respetan **el mismo orden** (A antes que B antes que C).
    El primero que consigue A tiene paso libre al resto; el otro espera en A **sin retener nada**. No
    puede haber espera circular, que es condición necesaria del deadlock.
- enunciado: b) ¿Por qué el SO bloquearía al proceso 1 al pedir B o C, aun estando libres?
  opciones:
  - texto: 'Porque aplica evasión: dárselos podría llevar a un estado inseguro'
    explicacion: Correcta.
  - texto: Porque aplica prevención por orden y P1 pide B antes que A
    explicacion: La prevención se define al programar; el SO no bloquea un pedido de un recurso libre
      por eso.
  - texto: Porque detectó un deadlock y lo está recuperando
    explicacion: La detección actúa después de que el deadlock ocurre, no antes de asignar.
  - texto: Porque P1 tiene menor prioridad que P2 y P3
    explicacion: La prioridad es de planificación, no de asignación de recursos.
  correcta: 0
  justificacion: |
    Es **evasión** (tipo algoritmo del banquero): el SO asigna solo si el estado resultante es
    **seguro**. Si A ya está tomado (por P2 o P3), darle B a P1 puede ser inseguro: P1 después podría
    pedir A (si se cumple `cond`) mientras el dueño de A espera B o C, que tiene P1. Por eso lo bloquea
    aunque B y C estén libres.

Dado un sistema concurrente en el que se tienen 3 procesos con el siguiente pseudocódigo (recursos compartidos: **A = 1; B = 1; C = 1**):

<div class="codigo-columnas">

**Proceso 1**

```c
pedir_recurso(B);
pedir_recurso(C);
if (cond) {
  pedir_recurso(A);
}
hacerCosas();
// finaliza y libera
```

**Proceso 2**

```c
while(1) {
  pedir_recurso(A);
  pedir_recurso(C);
  hacerCosas();
  liberar_recursos();
}
```

**Proceso 3**

```c
while(1) {
  pedir_recurso(A);
  pedir_recurso(B);
  pedir_recurso(C);
  hacerCosas();
  liberar_recursos();
}
```

</div>

a) ¿Podría generarse deadlock si se ejecutaran únicamente los procesos 2 y 3? En caso afirmativo, muestre un ejemplo de cómo se generaría el mismo; en caso negativo, justifique apropiadamente.

b) Al ejecutar los 3 procesos, suele ocurrir que el SO bloquea al proceso 1 tras pedir el recurso B o el recurso C, incluso cuando estos dos recursos estuvieran libres. ¿A qué podría deberse esto?
