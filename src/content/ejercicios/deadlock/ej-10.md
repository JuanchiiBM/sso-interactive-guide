    explicacion: 'P1 no retiene nada: no puede ser parte de una espera circular.'
  - texto: 'Sí, entre P2 y P3: P2 → R3 → P3 → R1 → P2'

    ```grafo
    procesos: P1, P2, P3

    R2 -> P2

    R3 -> P3
    P1 -> R2
    P1 -> R1

    resaltar-ciclo
    ```

    Hay una **espera circular** `P2 → R3 → P3 → R1 → P2`, y los dos recursos del ciclo (R1 y R3) tienen

    libre de R2 no ayuda, porque ninguno de los dos la está esperando.
- enunciado: b) ¿Sufre algún proceso inanición o hace espera activa?
  opciones:
  - texto: 'P1: nunca obtiene R1 y pregunta sin bloquearse, o sea, espera activa'
    explicacion: Correcta.
  - texto: 'P3: espera R1 para siempre, así que hace espera activa'
    explicacion: 'P3 está bloqueado (en deadlock), no consumiendo CPU: eso no es espera activa.'
  - texto: 'Ninguno: P1 no se bloquea, así que no puede sufrir inanición'
    explicacion: La inanición es no conseguir nunca el recurso, esté o no bloqueado.
  - texto: 'P2: retiene R1 y R2, así que es el que hace espera activa'
    explicacion: 'P2 está bloqueado esperando R3: no ocupa la CPU.'
  correcta: 0
  justificacion: |
    - **Inanición:** P1 jamás va a conseguir R1, que está tomado por P2 (en deadlock).
    - **Espera activa:** P1 consulta en un `while(1)` con una función **no bloqueante**. Está esperando
      un evento (que se libere R1) **consumiendo CPU** en cada vuelta en lugar de bloquearse, y el
      evento no va a ocurrir nunca.

Se tienen los siguientes procesos simulando el proceso de corrección de parciales en un sistema, representados en un grafo de asignación de recursos, en un momento dado:

```grafo
procesos: P1, P2, P3
recursos: R1, R2x2, R3
R2 -> P2
R1 -> P2
R3 -> P3
P1 -> R2
P1 -> R1
P3 -> R1
P2 -> R3
```

Se sabe que P2 y P3 son procesos encargados de corregir parciales, y para ello necesitan acceder a los distintos recursos (R1, R2, R3). P1 es un proceso que tiene como objetivo consultar las notas de los mismos, y para ello pregunta insistentemente utilizando el siguiente código:

```c
while(1) { preguntar_notas_ya(); }
```

`preguntar_notas_ya()` es una función **no bloqueante** que permite la continuación del proceso si los recursos R1 y R2 no están disponibles al mismo tiempo.

a) ¿Presenta el sistema un deadlock? En caso afirmativo, indique el por qué, los procesos y los recursos involucrados. En caso negativo, provea una secuencia posible de finalización.

b) ¿Sufre algún proceso de inanición? De ser así, indique cuál/es y la razón. ¿Existe algún proceso realizando una espera activa? Defina el concepto y explique en dónde ocurriría.
