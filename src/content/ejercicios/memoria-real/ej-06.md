calculos:
  - enunciado: 'a) ¿A qué direcciones físicas corresponden las direcciones lógicas? (en hexadecimal)'
    fault: true
    campos:
      - { etiqueta: '`02ABh`', respuesta: '07AB', base: 16 }
      - { etiqueta: '`C110h`', respuesta: '1510', base: 16 }
      - { etiqueta: '`8013h`', respuesta: '0913', base: 16 }
      - { etiqueta: '`01FAh`', respuesta: '12FA', base: 16 }
    justificacion: |
      Páginas de 256 B → **8 bits de offset**. 4 segmentos → **2 bits de segmento**. Quedan
      16 − 2 − 8 = **6 bits de página**: `segmento (2) | página (6) | offset (8)`.

      | DL | Binario | Seg. | Pág. | Frame | DF |
      | --- | --- | --- | --- | --- | --- |
      | 02ABh | `00 000010 10101011` | 0 (Code) | 2 | 7 | **07ABh** |
      | C110h | `11 000001 00010000` | 3 (Heap) | 1 | 21 = 15h | **1510h** |
      | 8013h | `10 000000 00010011` | 2 (Stack) | 0 | 9 | **0913h** |
      | 01FAh | `00 000001 11111010` | 0 (Code) | 1 | 18 = 12h | **12FAh** |

      La DF es `frame | offset`: como el frame es de 256 B, el offset son los dos últimos dígitos
      hexa y el frame, los de adelante. Ninguna cae en una página sin frame, así que no hay fault.
  - enunciado: 'b) ¿Cuál es el tamaño máximo teórico y real de un proceso?'
    campos:
      - { etiqueta: Teórico, respuesta: 64, unidad: KiB }
      - { etiqueta: Real, respuesta: 32, unidad: KiB }
    justificacion: |
      - **Teórico:** lo que direcciona la DL, `2^16 B = 64 KiB`.
      - **Real:** sin memoria virtual el proceso tiene que estar entero en RAM, así que no puede
        superar los **32 KiB** de memoria física.
  - enunciado: 'd) ¿Cuál es el máximo de fragmentación interna por proceso?'
    campos:
      - { etiqueta: Fragmentación interna máxima, respuesta: 1020, unidad: bytes }
    justificacion: |
      En segmentación paginada cada segmento se parte en páginas, y solo la **última página de
      cada segmento** puede quedar casi vacía: usa 1 byte y desperdicia 255.
      Con 4 segmentos: `255 B × 4 = 1020 B`.
preguntas:
  - enunciado: 'c) Hay solo 6 frames libres. ¿Se puede cargar otra instancia del Programa X sin finalizar ni descargar ningún proceso?'
    opciones:
      - texto: 'No: la instancia necesita 9 frames y hay solo 6 libres'
        explicacion: 'Cuenta bien los 9 frames, pero se olvida de que el código se puede compartir.'
      - texto: 'Sí: se carga parcialmente con 6 frames y el resto de las páginas se trae cuando haga falta'
        explicacion: 'El sistema no tiene memoria virtual: el proceso tiene que estar entero en RAM.'
      - texto: 'Sí: el nuevo proceso comparte con P1 las páginas del segmento de código y solo necesita 6 frames propios'
        explicacion: Correcta.
      - texto: 'Sí: el nuevo proceso comparte con P1 el segmento de datos, que ya tiene sus frames cargados'
        explicacion: 'Los datos se modifican (RW): si se comparten, una instancia pisaría los datos de la otra.'
    correcta: 2
    justificacion: |
      P1 usa **9 frames**: 3 de Code, 2 de Data, 1 de Stack y 3 de Heap. Con 6 libres no entra otra
      copia completa.

      Pero el segmento de **código** es de solo lectura y ejecución (RX): nunca se modifica, así que
      dos instancias del mismo programa pueden usar los **mismos frames**. Alcanza con que la tabla
      de páginas del segmento 0 del nuevo proceso apunte a los frames 3, 18 y 7. Entonces el nuevo
      proceso solo necesita frames para Data, Stack y Heap: `2 + 1 + 3 = 6`, justo los que hay.

Un sistema de 16 bits, sin memoria virtual y con 32 KiB de memoria física utiliza segmentación
paginada. Los procesos poseen 4 segmentos (en orden: Code, Data, Stack y Heap) y se sabe que cada
página posee un tamaño de 256 bytes. Se conocen las tablas de páginas de los segmentos del proceso
P1, que corresponde al Programa X:

| Code – S0 | | Data – S1 | | Stack – S2 | | Heap – S3 | |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **Marco** | **Permisos** | **Marco** | **Permisos** | **Marco** | **Permisos** | **Marco** | **Permisos** |
| 3 | RX | 11 | RW | 9 | RW | 10 | RW |
| 18 | RX | 17 | RW | – | – | 21 | RW |
| 7 | RX | – | – | – | – | 24 | RW |

R: read · W: write · X: execute

a) ¿A qué direcciones físicas corresponden las direcciones lógicas 02ABh, C110h, 8013h, 01FAh?

b) ¿Cuál es el tamaño máximo teórico y real de un proceso?

c) Sabiendo que actualmente sólo hay 6 marcos libres en memoria, ¿es posible cargar otra
instancia del Programa X en memoria sin finalizar ni descargar ninguno del resto de los procesos
en memoria? De ser posible, ¿cómo lo haría?

d) ¿Cuál es el máximo de fragmentación interna por proceso?
