calculos:
  - enunciado: 'El proceso intenta **escribir** en cada dirección virtual. Si la escritura se hace, ¿en qué dirección física? Si no, marcá **Fault**.'
    fault: true
    campos:
      - { etiqueta: '`20000h`', respuesta: '1B800', base: 16 }
      - { etiqueta: '`10000h`', respuesta: fault, base: 16 }
      - { etiqueta: '`0BEEFh`', respuesta: fault, base: 16 }
      - { etiqueta: '`00ACEh`', respuesta: fault, base: 16 }
    justificacion: |
      Las direcciones tienen 18 bits: los **2 primeros** son el segmento y los **16 restantes**, el
      desplazamiento. Los 16 bits de desplazamiento son justo los **4 últimos dígitos hexa**; el
      primer dígito (que vale 0 a 3) es el segmento.

      | Virtual | Binario (seg · desplazamiento) | Seg | Desplaz. | ¿< largo? | Permiso | Resultado |
      | --- | --- | --- | --- | --- | --- | --- |
      | 20000h | `10` · `0000 0000 0000 0000` | 2 | 0000h | 0 < FFFh ✓ | R/W ✓ | 1B800h + 0 = **1B800h** |
      | 10000h | `01` · `0000 0000 0000 0000` | 1 | 0000h | 0 < 7FFh ✓ | Exec ✗ | **Fault** |
      | 0BEEFh | `00` · `1011 1110 1110 1111` | 0 | BEEFh | BEEFh ≥ ABCDh ✗ | — | **Fault** |
      | 00ACEh | `00` · `0000 1010 1100 1110` | 0 | 0ACEh | ACEh < ABCDh ✓ | Read ✗ | **Fault** |

      Solo 20000h llega a la memoria: es el primer byte del segmento 2, que es de lectura y escritura.
preguntas:
  - enunciado: '¿Qué provoca cada fault?'
    opciones:
      - texto: '`10000h`: desplazamiento fuera del segmento · `0BEEFh`: permiso · `00ACEh`: permiso'
        explicacion: 'El desplazamiento de 10000h es 0, que entra en cualquier segmento.'
      - texto: '`10000h`: permiso · `0BEEFh`: desplazamiento fuera del segmento · `00ACEh`: permiso'
        explicacion: 'Correcta: el segmento 1 es solo de ejecución, BEEFh se pasa del largo ABCDh y el segmento 0 es solo de lectura.'
      - texto: '`10000h`: permiso · `0BEEFh`: permiso · `00ACEh`: desplazamiento fuera del segmento'
        explicacion: 'ACEh es mucho menor que el largo ABCDh: el desplazamiento de 00ACEh es válido.'
      - texto: 'Las tres por desplazamiento fuera del segmento'
        explicacion: 'Solo 0BEEFh se pasa del largo; las otras dos están dentro de su segmento pero no permiten escribir.'
    correcta: 1
    justificacion: |
      La MMU hace **dos chequeos** y cualquiera de los dos genera una interrupción:

      1. **Límite:** `desplazamiento < largo`. Si falla → **segmentation fault**.
      2. **Protección:** el modo de acceso tiene que estar permitido. Si falla → **interrupción por
         modo de acceso inválido**.

      - **10000h** (seg 1, desplazamiento 0): está dentro, pero el segmento 1 es **Exec only**. No se
        puede escribir en código → error de **permiso**.
      - **0BEEFh** (seg 0, desplazamiento BEEFh): BEEFh ≥ ABCDh, se sale del segmento →
        **segmentation fault**. Aunque además sea un segmento de solo lectura, el desplazamiento ya
        invalida el acceso.
      - **00ACEh** (seg 0, desplazamiento 0ACEh): está dentro, pero el segmento 0 es **Read only** →
        error de **permiso**.

Considere una máquina con direcciones de 18 bits. Los primeros 2 bits se utilizan para identificar
el segmento, y los últimos 16, el offset dentro del segmento. Asumir que las bases y los límites de
la tabla de segmentos están configuradas de la siguiente forma:

| Segmento | Base   | Largo  | Protección |
| -------- | ------ | ------ | ---------- |
| 0        | 00000h | 0ABCDh | Read only  |
| 1        | 1B000h | 007FFh | Exec only  |
| 2        | 1B800h | 00FFFh | Read write |
| 3        | 30000h | 01234h | Read write |

Responder en forma clara y concisa qué sucede cuando el proceso intenta escribir en cada una de las
siguientes direcciones virtuales: 20000h, 10000h, 0BEEFh, 00ACEh.
