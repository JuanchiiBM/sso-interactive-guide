calculos:
  - enunciado: 'a) Tamaño máximo posible de un programa a ejecutar en el sistema (ignorando el espacio ocupado por el SO).'
    campos:
      - { etiqueta: 'Tamaño máximo', respuesta: 256, unidad: KiB }
    justificacion: |
      Hay dos límites, y manda el más chico:

      - **Espacio lógico:** 20 bits → 2<sup>20</sup> bytes = **1 MiB**. Es lo máximo que el proceso
        puede direccionar.
      - **Memoria real:** **256 KiB** = 64 frames de 4 KiB.

      Como es paginación **simple** (sin memoria virtual), todas las páginas del programa tienen que
      estar cargadas a la vez. Un programa de más de 64 páginas no tiene dónde ponerlas, así que el
      máximo es **256 KiB**.
  - enunciado: 'b) Cantidad máxima en bytes de fragmentación interna (por proceso) y externa que podría existir.'
    campos:
      - { etiqueta: 'Fragmentación interna', respuesta: 4095, unidad: bytes }
      - { etiqueta: 'Fragmentación externa', respuesta: 0, unidad: bytes }
    justificacion: |
      **Fragmentación interna:** está en la **última página** del proceso, que puede quedar a medio
      usar. El peor caso es que esa página tenga **1 solo byte** ocupado:

      4096 − 1 = **4095 bytes** desperdiciados por proceso. No llega a 4096: una página sin ningún
      byte usado no se le asignaría.

      **Fragmentación externa:** **0 bytes**. Los frames tienen todos el mismo tamaño y una página
      puede ir a cualquier frame libre, contiguo o no. Nunca queda un hueco libre que sea demasiado
      chico para usarse.
---

Dado un sistema con una administración de memoria paginada simple (o sea, sin memoria virtual), con
256 KiB¹ de memoria real, 20 bits de direccionamiento lógico y páginas de 4 KiB, se pide:

- Tamaño máximo posible de un programa a ejecutar en el sistema (ignorando el espacio ocupado por el
  SO).
- Cantidad máxima en bytes de fragmentación interna (por proceso) y externa que podría existir.

¹ 1 KiB es el equivalente a 1024 bytes (1 KB, por el contrario, formalmente representa 1000 bytes).
