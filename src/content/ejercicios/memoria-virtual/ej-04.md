nota: |
  Convención de la cátedra: los PF de la **carga inicial cuentan** (los frames arrancan vacíos). En
  Clock, la página entra con U = 1, el puntero avanza al frame siguiente y un acierto no lo mueve.
calculos:
  - enunciado: 'a) ¿Cuántos fallos de página ocurren con cada algoritmo?'
    campos:
      - { etiqueta: 'Óptimo', respuesta: 6, unidad: PF }
      - { etiqueta: 'FIFO', respuesta: 7, unidad: PF }
      - { etiqueta: 'LRU', respuesta: 8, unidad: PF }
      - { etiqueta: 'Clock', respuesta: 7, unidad: PF }
    justificacion: |
      Recorré cada algoritmo con las pestañas. Los 4 primeros PF son la carga inicial (0, 1, 7 y 2
      entran en los 4 frames vacíos) y son iguales en todos.

      ```recorrido guia-mem-ej8
      ```

      | Algoritmo | Carga inicial | Con reemplazo | Total |
      | --- | --- | --- | --- |
      | Óptimo | 4 | 2 | **6** |
      | FIFO | 4 | 3 | **7** |
      | LRU | 4 | 4 | **8** |
      | Clock | 4 | 3 | **7** |

      **Óptimo** es el mínimo posible: siempre saca la página que más tarde se vuelve a usar. No se
      puede implementar (necesita conocer el futuro), pero sirve de referencia para comparar.
      En esta secuencia **LRU** queda peor que FIFO y Clock: el 3 y el 2 se usan con un patrón que
      hace que la menos usada recientemente sea justo la que se vuelve a pedir enseguida.
preguntas:
  - enunciado: 'b) Proponé un formato de entrada de la tabla de páginas para Clock, sabiendo que los procesos pueden leer, escribir y ejecutar según los permisos de la página, con una memoria física de 64 KiB y frames de 2 KiB.'
    opciones:
      - texto: 'P + U + M + número de frame (5 bits)'
        explicacion: 'Faltan los permisos, y M lo necesita el Clock mejorado, no el Clock simple.'
      - texto: 'P + permisos R/W/X + número de frame (5 bits)'
        explicacion: 'Falta el bit de uso (U): es lo que mira Clock para elegir la víctima.'
      - texto: 'P + U + permisos R/W/X + número de frame (6 bits)'
        explicacion: 'Sobra un bit de frame: 64 KiB / 2 KiB = 32 frames se numeran con 5 bits.'
      - texto: 'P + U + permisos R/W/X + número de frame (5 bits)'
        explicacion: 'Correcta: presencia, uso para Clock, los tres permisos y 5 bits para 32 frames.'
    correcta: 3
    justificacion: |
      | P | U | R | W | X | Frame |
      | --- | --- | --- | --- | --- | --- |
      | 1 bit | 1 bit | 1 bit | 1 bit | 1 bit | 5 bits |

      - **P (presencia):** si la página está en memoria. Con P = 0, referenciarla es un page fault.
      - **U (uso):** lo prende el hardware en cada referencia; Clock lo baja al pasar el puntero y
        reemplaza la primera página que encuentra con U = 0.
      - **R / W / X:** permisos de lectura, escritura y ejecución. Un acceso no permitido genera
        una interrupción.
      - **Frame:** 64 KiB / 2 KiB = 2<sup>16</sup> / 2<sup>11</sup> = 32 frames → **5 bits**.

      En total, **10 bits** por entrada. El bit de **modificado (M)** no hace falta para el Clock
      simple, aunque en la práctica se agrega para saber si la víctima hay que escribirla en disco
      (y es imprescindible en el Clock mejorado).

Un proceso de 8 páginas está ejecutando en un sistema de memoria virtual, con asignación fija de 4
marcos por proceso y alcance local. Si se considera que la memoria está inicialmente vacía,
determinar el número de fallos de página que ocurren al referenciarse las siguientes páginas:
0, 1, 7, 2, 3, 2, 7, 1, 0, 3, 0, 2, 3, 1; bajo los siguientes algoritmos:

- Óptimo, FIFO, LRU, Clock
- Proponga para el algoritmo Clock un formato para la entrada de la tabla de páginas, sabiendo que
  los procesos pueden leer/escribir/ejecutar siempre y cuando los permisos de la página lo permitan,
  con una memoria física de 64 KiB y frames de 2 KiB.
