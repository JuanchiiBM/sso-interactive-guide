calculos:
  - enunciado: 'a) Dirección física de cada dirección lógica de A (hexadecimal) y frame asignado.'
    campos:
      - { etiqueta: '`A1012222h`', respuesta: '000A2222', base: 16 }
      - { etiqueta: '`030110A1h`', respuesta: '001510A1', base: 16 }
      - { etiqueta: '`03030000h`', respuesta: '000B0000', base: 16 }
      - { etiqueta: Page faults, respuesta: 1, unidad: PF }
      - { etiqueta: Frame asignado por el PF, respuesta: '0015', base: 16 }
    justificacion: |
      La tabla de 1er nivel tiene 256 entradas → **8 bits** para el 1er nivel y, por enunciado, otros
      **8** para el 2do. La DL de 32 bits queda `nivel 1 (8) | nivel 2 (8) | offset (16)`: los
      primeros 4 dígitos hexa son la página y los últimos 4, el offset.

      Recorré las tres traducciones con **Siguiente**: el corte, la TLB, las dos tablas, el bitmap
      cuando hay PF y la DF.

      ```tlb
      titulo: Traducciones de A con dos niveles, TLB y bitmap
      niveles: [8, 8]
      bitsOffset: 16
      bitsFrame: 16
      entradas: 8 # la TLB tiene lugar
      tlb:
        - { pagina: 0x1020, frame: 0x0011, proceso: A }
        - { pagina: 0xA101, frame: 0x000A, proceso: A }
        - { pagina: 0x0301, frame: 0x00AA, proceso: B }
        - { pagina: 0x1111, frame: 0x0010, proceso: A }
        - { pagina: 0x0022, frame: 0x0004, proceso: C }
      tp1: { 0x02: 0xFFF10000, 0x03: 0xFFF30000, 0x04: 0xFFF50000 }
      tablas:
        0xFFF30000:
          0x00: { frame: 0x000F, p: 0 }
          0x01: { frame: 0x000C, p: 0 }
          0x02: { frame: 0x0002, p: 1 }
          0x03: { frame: 0x000B, p: 1 }
          0x04: { frame: 0x0001, p: 0 }
      bitmap: { desde: 0x15, bits: [0, 1, 1, 0, 1, 1, 1, 1, 1, 0] }
      referencias:
        - { proceso: A, dl: 0xA1012222 }
        - { proceso: A, dl: 0x030110A1 }
        - { proceso: A, dl: 0x03030000 }
      ```

      Accesos a memoria: el 1 no lee tablas (solo el dato); el 2 y el 3 leen TP1 y TP2 y después el
      dato (el 2, además, reintenta la traducción tras el PF).
preguntas:
  - enunciado: 'b) ¿Qué habría cambiado si la TLB no tuviera la columna "Proceso"?'
    opciones:
      - texto: 'Nada: la TLB guarda páginas y frames, el proceso no influye en la traducción'
        explicacion: 'Sí influye: la página 0301 existe en la TLB, pero es de B.'
      - texto: 'La 2da traducción: A tomaría la entrada 0301 → 00AA de B y leería memoria de otro proceso (00AA10A1h)'
        explicacion: Correcta.
      - texto: 'La 1ra traducción: la A101 daría miss porque la TLB ya no puede distinguir de quién es cada entrada'
        explicacion: 'Sin la columna, la entrada A101 sigue estando y daría hit igual: lo que se pierde es distinguir al dueño, no la entrada.'
      - texto: 'La 3ra traducción: la 0303 daría page fault, porque sin el proceso no se sabe qué tabla consultar'
        explicacion: 'La 0303 no está en la TLB con o sin la columna: se resuelve con las tablas del proceso en ejecución, que el SO conoce igual.'
    correcta: 1
    justificacion: |
      La columna "Proceso" (ASID) es lo que permite tener en la TLB entradas de varios procesos a la
      vez. Sin ella, la búsqueda de la página 0301 daría **hit** con la entrada de B y A obtendría
      **00AA10A1h**: una dirección de la memoria de otro proceso. Por eso, una TLB sin ASID tiene
      que **vaciarse en cada cambio de proceso**.

Un sistema utiliza **paginación jerárquica**, dedicando igual cantidad de bits para sus dos
niveles. Se sabe que el sistema posee el bitmap en el estado indicado debajo, y realiza una
asignación ascendente por cada pedido encontrando el primero libre. La tabla de páginas del primer
nivel tiene 256 entradas. En este momento comienza a ejecutar el proceso A.

**TP 1er nivel / principal**

| Página | Puntero hacia el comienzo de la tabla de páginas del siguiente nivel |
| ------ | -------------------------------------------------------------------- |
| 00     | FFG10000h                                                            |
| 01     | FFG20000h                                                            |
| 02     | FFF10000h                                                            |
| 03     | FFF30000h                                                            |
| 04     | FFF50000h                                                            |
| …      | …                                                                    |

| TP 2do nivel – comienzo en FFF30000h |           |               | TP 2do nivel – comienzo en FFG20000h |           |               |
| ------------------------------------ | --------- | ------------- | ------------------------------------ | --------- | ------------- |
| **Página**                           | **Frame** | **Presencia** | **Página**                           | **Frame** | **Presencia** |
| 00                                   | 000F      | 0             | 00                                   | 000C      | 0             |
