nota: |
  Una dirección que cae **fuera del espacio del proceso** no es un page fault: es un error de

  - enunciado: 'Primero: ¿a qué página corresponde cada dirección? (páginas de 8 KB)'
    fault: true
    campos:
      - { etiqueta: '`100` (L)', respuesta: 0 }
      - { etiqueta: '`122950` (E)', respuesta: 15 }
      - { etiqueta: '`98306` (L)', respuesta: 12 }
      - { etiqueta: '`139264` (E)', respuesta: 17 }
      - { etiqueta: '`122880` (L)', respuesta: 15 }
      - { etiqueta: '`155650` (E)', respuesta: 19 }
      - { etiqueta: '`172100` (L)', respuesta: fault }
      - { etiqueta: '`100` (L)', respuesta: 0 }
    justificacion: |
      Página = dirección ÷ 8192 (división entera). El proceso mide 159 KB: 159 / 8 = 19,875 → ocupa
      **20 páginas, de la 0 a la 19**.

      | Dirección | ÷ 8192 | Página |
      | --- | --- | --- |
      | 100 | 0,01 | **0** |
      | 122950 | 15,01 | **15** |
      | 98306 | 12,0002 | **12** |
      | 139264 | 17 exacto | **17** |
      | 122880 | 15 exacto | **15** |
      | 155650 | 19,0002 | **19** |
      | 172100 | 21,01 | 21 → **fuera del proceso** |
      | 100 | 0,01 | **0** |

      La página 21 no existe en un proceso de 20 páginas: la MMU detecta una **dirección
      inválida** (el SO la trataría como segmentation fault). No es un page fault, porque no hay
      ninguna página que traer de disco.
  - enunciado: 'a) Con LRU y con Clock mejorado: ¿cuántos page faults hay y cuántas páginas se escriben a disco?'
    campos:
      - { etiqueta: 'LRU · page faults', respuesta: 6, unidad: PF }
      - { etiqueta: 'LRU · escritas a disco', respuesta: 2, unidad: pág. }
      - { etiqueta: 'Clock mejorado · page faults', respuesta: 5, unidad: PF }
      - { etiqueta: 'Clock mejorado · escritas a disco', respuesta: 1, unidad: pág. }
    justificacion: |
      Recorré los dos algoritmos con las pestañas. Cada celda muestra la página y sus bits
      prendidos (**U** uso, **M** modificado); la fila **A disco** indica la víctima que se escribe
      porque tenía M = 1.

      ```recorrido guia-mem-ej9
      ```

      | | LRU | Clock mejorado |
      | --- | --- | --- |
      | Page faults | **6** | **5** |
      | Escritas a disco | **2** (19 y 14) | **1** (14) |
      | Estado final | M1: 17, M3: 15, M5: 0, M8: 19 | M1: 17, M3: 15, M5: 19, M8: 0 |

      - **Ref. 1 (página 0):** el frame 8 está libre, así que es PF pero sin víctima.
      - **LRU** saca la página referenciada hace más tiempo. Saca a la 19 y a la 14, que estaban
        modificadas, y las dos se escriben a disco. Además saca a la 19 justo antes de que se vuelva
        a escribir: eso le cuesta un PF más.
      - **Clock mejorado** prefiere víctimas con M = 0, porque reemplazarlas no exige escribir. Así
        mantiene la 19 en memoria y solo escribe la 14, cuando ya no quedaba ninguna (0,0).
preguntas:
  - enunciado: 'b) ¿Cuál de los dos algoritmos rinde mejor con esta secuencia, y con qué criterio?'
    opciones:
      - texto: 'LRU, porque elige la víctima con información exacta de cuándo se usó cada página'
        explicacion: 'Que la información sea más precisa no garantiza un mejor resultado: acá LRU hace más PF y más escrituras.'
      - texto: 'Clock mejorado, por tener menos accesos a disco: 5 PF + 1 escritura contra 6 PF + 2 escrituras'
        explicacion: 'Correcta: el costo dominante es ir a disco, tanto para traer páginas como para escribir víctimas modificadas.'
      - texto: 'Clock mejorado, solo porque es más barato de implementar que LRU'
        explicacion: 'El enunciado pide dejar de lado el costo de implementación: hay que comparar con la secuencia dada.'
      - texto: 'Rinden igual: los dos terminan con las mismas páginas en memoria'
        explicacion: 'Terminan con las mismas páginas, pero en el camino uno va más veces a disco que el otro.'
    correcta: 1
    justificacion: |
      El criterio es la **cantidad de accesos a disco**, que es lo que realmente cuesta tiempo:

      - cada **page fault** obliga a **leer** la página de disco;
      - cada víctima con **M = 1** obliga además a **escribirla** antes de reemplazarla.

      | | Lecturas (PF) | Escrituras | Accesos a disco |
      | --- | --- | --- | --- |
      | LRU | 6 | 2 | **8** |
      | Clock mejorado | 5 | 1 | **6** |

      **Clock mejorado** rinde mejor: hace menos PF y además escribe menos, porque prefiere como
      víctima una página no modificada. LRU es "más preciso" mirando el pasado, pero no tiene en
      cuenta el bit M y con esta secuencia termina sacando páginas modificadas que se vuelven a
      usar.

Se tiene una PC con procesador Intel de 32 bits de direccionamiento que acepta el uso de páginas de
8 KB de tamaño. Dicha PC cuenta, además, con un sistema operativo que utiliza paginación bajo demanda
donde la política de asignación de frames es fija, siendo de 4 frames por proceso. La política de
sustitución de páginas es local.

Se está ejecutando un proceso de 159 KB de tamaño con la siguiente asignación actual de frames:

| Puntero (si aplica) | Marco | Página (numerada desde 0) | Uso | Modificado | Instante de referencia |
| ------------------- | ----- | ------------------------- | --- | ---------- | ---------------------- |
|                     | 1     | 14                        | 1   | 1          | 28                     |
|                     | 3     | 17                        | 1   | 0          | 3                      |
|                     | 5     | 19                        | 1   | 1          | 15                     |
| →                   | 8     | –                         | –   | –          | –                      |

A continuación se detallan las próximas referencias a memoria (con sus respectivos modos de acceso)
que el proceso realizará:

100 (Lectura) – 122950 (Escritura) – 98306 (Lectura) – 139264 (Escritura) – 122880 (Lectura) –
155650 (Escritura) – 172100 (Lectura) – 100 (Lectura)

Se pide, para los algoritmos LRU y Clock modificado:

a) Indicar el estado de las páginas en memoria luego de cada referencia, así como también los page
faults producidos y las páginas que fueron escritas a disco. No es necesario calcular los instantes
de referencia.

b) Dejando a un lado el costo de ejecución e implementación de un algoritmo de sustitución, indicar
cuál de los dos algoritmos presenta un mejor rendimiento con la secuencia de referencias dada. ¿Qué
criterio tiene en cuenta para tomar esa decisión?
