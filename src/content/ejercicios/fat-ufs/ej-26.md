calculos:
  - enunciado: 'a) Tamaño máximo teórico del File System y del archivo.'
    campos:
      - { etiqueta: 'File System teórico', respuesta: '2^44', unidad: B }
      - { etiqueta: 'Archivo máximo (exacto)', respuesta: 4198420, unidad: KiB }
    justificacion: |
      - **FS:** punteros de 4 B = 32 bits → `2^32 bloques × 2^12 B = 2^44 B` (16 TiB).
      - **Archivo:** punteros por bloque `4 KiB / 4 B = 2^10 = 1024`.

      | Punteros | Bloques de datos |
      | --- | --- |
      | 5 directos | 5 |
      | 1 indirecto simple | 2<sup>10</sup> = 1024 |
      | 1 indirecto doble | (2<sup>10</sup>)<sup>2</sup> = 1.048.576 |
      | **Total** | **1.049.605** |

      `1.049.605 × 4 KiB = 4.198.420 KiB ≈ 2^32 B` (4 GiB).
  - enunciado: 'b) ¿Cuánto espacio en disco ocupará `config_so`?'
    campos:
      - { etiqueta: 'Bloques ocupados', respuesta: 8, unidad: bloques }
      - { etiqueta: 'Espacio en disco', respuesta: 32, unidad: KiB }
    justificacion: |
      `25123 B / 4096 B = 6,13` → **7 bloques de datos**. Solo hay 5 directos: los 2 restantes van
      por el indirecto simple, que necesita **1 bloque de punteros**.

      `7 BD + 1 BP = 8 bloques` → `8 × 4 KiB = 32 KiB` (32768 B = 2<sup>15</sup> B).

      > La resolución oficial da "8 bloques (2^13 B)"; 8 × 4 KiB = 2^3 × 2^12 = **2^15 B**, no 2^13.
  - enunciado: 'c-ii) ¿Cuántos inodos se van a utilizar entre el archivo y su acceso directo?'
    campos:
      - { etiqueta: 'Inodos', respuesta: 2, unidad: inodos }
    justificacion: |
      | | `config_so` | acceso directo en `/home/Escritorio` |
      | --- | --- | --- |
      | FS | el de `/etc` | el de `/home` (otra partición) |
      | Tipo | regular | soft link |
      | Tamaño | 25123 B | largo de la ruta (`/etc/so/config_so`, ~17 B) |
      | Punteros en uso | 5 directos + indirecto simple | 1 directo |

      El acceso directo **tiene que ser un soft link**: está en otra partición, y un hard link es solo
      un número de inodo, que no tiene sentido en otro FS. El soft link es un archivo nuevo → su
      **propio inodo**. Total: **2 inodos**.
preguntas:
  - enunciado: 'c-i) ¿Cómo quedan las entradas de directorio?'
    opciones:
      - texto: '`/etc/so` tiene `config_so → X`; `/home/Escritorio` tiene una entrada que apunta al mismo inodo X del FS de `/etc`'
        explicacion: 'Eso es un hard link, y no puede cruzar a otra partición.'
      - texto: '`config_so → X` en `/etc/so`; `link_to_config_so → Y` en `/home/Escritorio`, Y del FS de `/home`'
        explicacion: Correcta.
      - texto: 'Solo cambia `/home/Escritorio`: el acceso directo reemplaza la entrada de `/etc/so`'
        explicacion: 'El original sigue en `/etc/so`; el acceso directo es una entrada más.'
      - texto: '`/etc/so` tiene `config_so → X` y además una entrada `link_to_config_so` que apunta a `/home`'
        explicacion: 'El acceso directo se crea en `/home/Escritorio`, no en `/etc/so`.'
    correcta: 1
    justificacion: |
      ```
      /etc/so          →  config_so          → inodo X   (FS de /etc)
      /home/Escritorio →  link_to_config_so  → inodo Y   (FS de /home)
      ```

      Como `/home` y `/etc` están en **particiones distintas**, el acceso directo es un **soft link**:
      una entrada en `/home/Escritorio` con su propio inodo, cuyo contenido es la ruta del original.
      Y puede ser numéricamente igual a X, pero es un inodo **de otro FS**.

El archivo nuevo `config_so` de tamaño 25123 bytes se guardará en el directorio `/etc/so` en un File
System EXT2 que usa bloques de 4 KiB y punteros de 4 bytes. Como debe modificarse varias veces, se
desea crear un acceso directo en `/home/Escritorio` para que sea rápidamente accesible. Los inodos
del EXT2 tienen 5 punteros directos, 1 indirecto simple y 1 indirecto doble. Además el directorio
`/home` y el directorio `/etc` se encuentran en diferentes particiones que contienen volúmenes con
las mismas características.

- a) ¿Cuál es el tamaño máximo teórico del archivo y del File System?
- b) ¿Cuánto espacio en disco ocupará el archivo `config_so`?
- c) En cuanto a `config_so` y su acceso directo:
  - i) Indique cómo quedarían las entradas de directorio.
  - ii) ¿Cuántos inodos se van a utilizar y qué información contendrán? (Puede incluir información
    no indicada en el enunciado para su respuesta).
