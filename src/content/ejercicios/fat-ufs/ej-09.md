calculos:
  - enunciado: 'a) Tamaño de cluster del filesystem A.'
    campos:
      - { etiqueta: 'Cluster de A', respuesta: 2, unidad: MiB }
    justificacion: |
      "Sin desperdiciar ningún bit" quiere decir que se usan **las 2<sup>16</sup> entradas** de FAT16
      y que, entre todas, cubren exactamente los 128 GiB:

      `2^16 × cluster = 128 GiB = 2^37 bytes → cluster = 2^37 / 2^16 = 2^21 bytes = 2 MiB`
  - enunciado: 'b) Tamaño de cluster del filesystem B, si la tabla FAT ocupa 256 MiB.'
    campos:
      - { etiqueta: 'Cluster de B', respuesta: 8, unidad: KiB }
    justificacion: |
      B ocupa el resto del disco: `512 GiB − 128 GiB = 384 GiB`.

      Cada entrada de FAT32 mide 4 bytes, así que la tabla tiene
      `256 MiB / 4 B = 2^28 / 2^2 = 2^26` entradas.

      Dividir directo da `384 GiB / 2^26 = 6 KiB`, que **no es un tamaño de cluster posible** (tiene
      que ser potencia de 2). Se sigue el criterio de la resolución del **1R 2C2025** (un disco de
      512 GiB con un volumen FAT16 y otro FAT32): la tabla tiene **2<sup>n</sup> entradas**, la
      menor potencia de 2 que alcanza para direccionar el volumen. Entonces se busca el cluster con
      el que 2<sup>26</sup> entradas cubren los 384 GiB:

      | Cluster | 2<sup>26</sup> × cluster | ¿Cubre 384 GiB? |
      | --- | --- | --- |
      | 4 KiB | 256 GiB | No |
      | **8 KiB** | **512 GiB** | **Sí** |

      Verificación: con clusters de 8 KiB, B tiene `384 GiB / 8 KiB = 3 × 2^24` clusters; para
      numerarlos hacen falta 26 bits (2<sup>25</sup> no alcanza), o sea 2<sup>26</sup> entradas ×
      4 B = **256 MiB**, el dato del enunciado. Con 4 KiB harían falta 2<sup>27</sup> entradas
      (512 MiB).
  - enunciado: 'c) Tamaño máximo teórico y real de ambos filesystems.'
    campos:
      - { etiqueta: 'A teórico', respuesta: 128, unidad: GiB }
      - { etiqueta: 'A real', respuesta: 128, unidad: GiB }
      - { etiqueta: 'B teórico', respuesta: 2048, unidad: GiB }
      - { etiqueta: 'B real', respuesta: 384, unidad: GiB }
    justificacion: |
      **Teórico** = clusters que numera el formato × cluster; **real** = el mínimo entre el teórico
      y el espacio asignado.

      - **A (FAT16):** `2^16 × 2 MiB = 2^16 × 2^21 = 2^37 bytes = 128 GiB`. Real:
        `min(128 GiB, 128 GiB) = 128 GiB`. Coinciden porque el cluster se eligió justo para eso.
      - **B (FAT32, 28 bits):** `2^28 × 8 KiB = 2^28 × 2^13 = 2^41 bytes = 2 TiB = 2048 GiB`.
        Real: `min(2 TiB, 384 GiB) = 384 GiB`: el límite es el espacio asignado.
  - enunciado: 'd) Máxima fragmentación interna en ambos filesystems (por archivo).'
    campos:
      - { etiqueta: 'A', respuesta: 2097151, unidad: bytes }
      - { etiqueta: 'B', respuesta: 8191, unidad: bytes }
    justificacion: |
      El peor caso es un archivo cuyo último cluster lleva **un solo byte**: se pierde un cluster
      menos 1 byte.

      - A: `2 MiB − 1 B = 2.097.152 − 1 = 2.097.151 bytes`.
      - B: `8 KiB − 1 B = 8.192 − 1 = 8.191 bytes`.

      Es el precio de A por cubrir 128 GiB con solo 16 bits: cada archivo chico puede desperdiciar
      casi 2 MiB.
  - enunciado: 'e) ¿Cuántos clusters son necesarios para guardar la tabla FAT del filesystem A?'
    campos:
      - { etiqueta: 'Clusters', respuesta: 1, unidad: clusters }
    justificacion: |
      Tabla de A: `2^16 entradas × 2 bytes = 2^17 bytes = 128 KiB`.

      Se guarda en clusters enteros: `⌈128 KiB / 2 MiB⌉ = 1 cluster`. Sobra casi todo el cluster
      (1.920 KiB): también la tabla sufre la fragmentación interna de un cluster tan grande.
  - enunciado: 'f) Tamaño máximo real de un archivo, considerando el espacio de las estructuras administrativas.'
    campos:
      - { etiqueta: 'A', respuesta: 131070, unidad: MiB }
      - { etiqueta: 'B', respuesta: 392960, unidad: MiB }
    justificacion: |
      En FAT un archivo puede usar todos los clusters del volumen (criterio de las resoluciones de
      parciales: archivo máximo = filesystem máximo). Ahora hay que descontar la **tabla FAT**, que
      ocupa clusters del mismo volumen:

      - **A:** la tabla ocupa 1 cluster (inciso e):
        `128 GiB − 1 × 2 MiB = 131.072 MiB − 2 MiB = 131.070 MiB`.
      - **B:** la tabla ocupa `256 MiB / 8 KiB = 2^28 / 2^13 = 2^15 = 32.768` clusters, exactos:
        `384 GiB − 256 MiB = 393.216 MiB − 256 MiB = 392.960 MiB`.
---

Se tiene un disco físico de 512 GiB, el cual tiene instalados dos filesystems de los cuales se
conoce:

- El filesystem A: FAT16 con 128 GiB asignados
- El filesystem B: FAT32

Responda las siguientes preguntas:

- a) ¿Cuál es el tamaño de cluster configurado para el filesystem A si se sabe que puede direccionar
  todo su espacio asignado sin desperdiciar ningún bit?
- b) ¿Cuál es el tamaño de cluster configurado para el filesystem B si se sabe que la tabla FAT ocupa
  256 MiB?
- c) Calcule el tamaño máximo teórico y real de ambos filesystems.
- d) Calcule la máxima fragmentación interna en ambos filesystems.
- e) ¿Cuántos clusters son necesarios para guardar la tabla FAT del filesystem A?
- f) Considerando el espacio utilizado por las estructuras administrativas, calcule para ambos
  filesystems el tamaño máximo real de un archivo.

> **Nota:** se asume que B ocupa el resto del disco (384 GiB). La tabla FAT tiene una entrada por
> cada número de cluster que hace falta direccionar, redondeado a potencia de 2 (criterio del 1R
> 2C2025); en f) las estructuras administrativas son **una** copia de la tabla FAT. En la
> implementación real, el campo "tamaño" de la entrada de directorio limita un archivo FAT a 4 GiB.
