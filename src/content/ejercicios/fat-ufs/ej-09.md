  - enunciado: 'a) Leer el byte nro. 16777227 de un archivo.'
    campos:
      - { etiqueta: 'Bloque lógico del archivo', respuesta: 4096 }
      - { etiqueta: 'Accesos a bloques', respuesta: 3 }
    justificacion: |
      **Criterio de la cátedra** (resoluciones de parciales): se cuentan los bloques de **datos** y
      de **punteros** que se leen. El inodo **no** cuenta: el archivo está abierto y su inodo, en
      memoria. Los bytes y los bloques se numeran desde 0.

      **Punteros por bloque:** `4 KiB / 8 bytes = 2^12 / 2^3 = 512`. Rango de bloques lógicos que
      cubre cada puntero del inodo:

      | Puntero | Bloques lógicos |
      | --- | --- |
      | 12 directos | 0 a 11 |
      | Indirecto simple | 12 a 523 (512) |
      | Indirecto doble | 524 a 262.667 (512<sup>2</sup> = 262.144) |
      | Indirecto triple | 262.668 en adelante |

      **Bloque del byte:** `16.777.227 / 4096 = 4096` (resto 11), porque 16.777.216 = 2<sup>24</sup> =
      4096 × 4096. El bloque 4096 cae en el **indirecto doble**.

      **Accesos:** bloque de punteros del doble → bloque de punteros simple → bloque de datos =
      **3 accesos**.
  - enunciado: 'b) Leer desde el byte 0 hasta el 250180 de un archivo.'
    campos:
      - { etiqueta: 'Bloques de datos', respuesta: 62 }
      - { etiqueta: 'Bloques de punteros', respuesta: 1 }
      - { etiqueta: 'Total de accesos', respuesta: 63 }
    justificacion: |
      **Último bloque:** `250.180 / 4096 = 61` (resto 324): se leen los bloques lógicos **0 a 61**, o
      sea **62 bloques de datos**.

      - Bloques 0 a 11: con los **12 directos**, sin bloques de punteros.
      - Bloques 12 a 61: 50 bloques por el **indirecto simple** → se lee **1 bloque de punteros**.

      Total: `62 datos + 1 de punteros = 63 accesos`. El bloque de punteros se lee una vez para los
      50 bloques que cubre.

Se tiene un sistema con ext2 como filesystem, con bloques de 4 KiB y punteros de 8 bytes. El inodo
está conformado con 12 punteros directos, 1 indirecto, 1 indirecto doble y 1 indirecto triple. Se
pide la cantidad de accesos a bloques necesaria para leer:

1. El byte nro 16777227 de un archivo
2. Desde el byte 0 hasta el 250180 de un archivo
