  En c), la tabla FAT está **cargada en memoria**: recorrerla no cuenta como lectura de disco.

calculos:
  - enunciado: 'a) Bloques del archivo que empieza en el bloque 5, en orden.'
    campos:
      - { etiqueta: '1.er bloque', respuesta: 5 }
      - { etiqueta: '2.º bloque', respuesta: 10 }
      - { etiqueta: '3.er bloque', respuesta: 6 }
      - { etiqueta: '4.º bloque', respuesta: 8 }
      - { etiqueta: '5.º bloque', respuesta: 3 }
    justificacion: |
      Cada entrada de la FAT guarda el **bloque siguiente** del archivo:

      ```
      5 → FAT[5] = 10 → FAT[10] = 6 → FAT[6] = 8 → FAT[8] = 3 → FAT[3] = Fin de Archivo
      ```

      El archivo tiene **5 bloques**: 5, 10, 6, 8 y 3.
  - enunciado: 'b) Tamaño del archivo con la mayor fragmentación interna posible.'
    campos:
      - { etiqueta: 'Tamaño del archivo', respuesta: 32769, unidad: bytes }
    justificacion: |
      La mayor fragmentación interna se da cuando del último bloque se usa **un solo byte**: 4 bloques
      llenos más 1 byte.

      `4 × 8192 + 1 =` **32769 bytes** (se desperdician 8191 B del último bloque).
  - enunciado: 'c) ¿En qué bloque está el byte 12.000 del archivo? ¿Cuántos bloques hay que leer para accederlo?'
    campos:
      - { etiqueta: 'Bloque del FS', respuesta: 10 }
      - { etiqueta: 'Bloques leídos', respuesta: 1, unidad: bloques }
    justificacion: |
      `12000 / 8192 = 1,46` → el byte está en el bloque **1 del archivo** (el 2.º, contando desde 0),
      que según la cadena es el **bloque 10** del FS.

      Para llegar se lee la entrada del directorio (bloque inicial 5) y `FAT[5] = 10`, todo en memoria.
      Del disco solo hace falta leer **1 bloque**: el 10.

      > La resolución oficial no contesta cuántos bloques se leen; el valor sale de suponer la FAT en
      > memoria (si se leyera la cadena de datos como en enlazada pura serían 2).
  - enunciado: 'd) Bloques del otro archivo del FS, en orden.'
    campos:
      - { etiqueta: '1.er bloque', respuesta: 2 }
      - { etiqueta: '2.º bloque', respuesta: 4 }
      - { etiqueta: '3.er bloque', respuesta: 7 }
    justificacion: |
      Hay solo dos "Fin de Archivo" (entradas 3 y 7): son dos archivos. Las entradas en 0 son bloques
      **libres** (0, 1, 9 y 11; el resto de la tabla también está en 0). Lo que no es del primer
      archivo ni está libre son 2, 4 y 7:

      ```
      2 → FAT[2] = 4 → FAT[4] = 7 → FAT[7] = Fin de Archivo
      ```

      Empieza en el **2**: ninguna entrada apunta a él.
  - enunciado: 'e) y f) Tamaño máximo teórico y real del FS.'
    campos:
      - { etiqueta: 'e) Teórico', respuesta: 2, unidad: TiB }
      - { etiqueta: 'f) Real', respuesta: 128, unidad: GiB }
    justificacion: |
      - **Teórico:** FAT32 usa 28 bits por entrada → `2^28 × 2^13 B = 2^41 B =` **2 TiB**.
      - **Real:** la FAT ocupa 64 MiB con entradas de 4 B → `2^26 / 2^2 = 2^24` entradas (bloques).
        `2^24 × 8 KiB = 2^37 B =` **128 GiB**.

Estas son las primeras 12 entradas de una tabla FAT que ocupa 64 MiB, de un file system FAT32 que
usa bloques de 8 KiB. El resto de las entradas de la tabla están en cero.

| Entrada | Valor |
| --- | --- |
| 0 | 0 |
| 1 | 0 |
| 2 | 4 |
| 3 | Fin de Archivo |
| 4 | 7 |
| 5 | 10 |
| 6 | 8 |
| 7 | Fin de Archivo |
| 8 | 3 |
| 9 | 0 |
| 10 | 6 |
| 11 | 0 |

Responda justificando las respuestas:

- a) Indique qué bloques tiene asignado el archivo que tiene como bloque inicial al n° 5 (iniciando
  la numeración en 0).
- b) Indique el tamaño del archivo asumiendo que tiene la mayor fragmentación interna posible.
- c) ¿En qué bloque se encuentra el byte n° 12.000 del archivo? ¿Cuántos bloques fueron necesarios
  leer para accederlo?
- d) Indique qué bloques tiene asignados el otro archivo del File System.
- e) Indique el tamaño máximo teórico del File System.
- f) Indique el tamaño máximo real del File System.
