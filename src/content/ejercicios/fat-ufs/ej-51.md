    justificacion: |
      **a)** "Soportaría hasta 16 TiB" es el máximo teórico: `2^32` bloques × tamaño de bloque =
      `2^44 B` → bloque = `2^44 / 2^32 = 2^12 B =` **4 KiB**.

      **b)** `1 TiB / 4 KiB = 2^40 / 2^12 =` **2<sup>28</sup>** bloques (268.435.456).

      **c)** Punteros por bloque: `2^12 / 2^2 = 2^10 = 1024`.

      | Punteros | Bloques de datos |
      | --- | --- |
      | 12 directos | 12 |
      | 1 indirecto simple | 2<sup>10</sup> = 1.024 |
      | 1 indirecto doble | 2<sup>20</sup> = 1.048.576 |
      | 1 indirecto triple | 2<sup>30</sup> = 1.073.741.824 |
      | **Total** | **1.074.791.436** |

      `1.074.791.436 × 4096 B =` **4.402.345.721.856 B ≈ 4,004 TiB** (lo que da la oficial). Es más
      que el volumen real (1 TiB): en la práctica el archivo lo limita el disco.

      **d)** Mismo bloque, punteros de 64 bits: `2^64 × 2^12 B =` **2<sup>76</sup> B** (64 ZiB).

Un sistema que posee un disco rígido de 1 TiB, está formateado con un File System EXT2 que utiliza
punteros de 32 bits. El tamaño real de dicho volumen es de 1 TiB, pero se sabe que soportaría un disco
de hasta 16 TiB sin problemas.

**Responda** las siguientes preguntas (de resultarle conveniente, puede dejar expresado el resultado
en potencia de 2):

a) ¿De qué tamaño es el bloque utilizado para formatear dicho volumen?

b) ¿Cuántos bloques existen en dicho sistema con el tamaño de disco actual?

c) ¿Cuál es el tamaño máximo teórico de archivo si se sabe que los inodos tienen 12 PD, 1 PIS, 1 PID y
1 PIT?

d) ¿Cuál sería el nuevo tamaño máximo teórico del File System, si se formateara con un EXT2 que use
punteros de 64 bits manteniendo el tamaño de bloque?
