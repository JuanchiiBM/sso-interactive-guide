tipo: practico

tags: [fat, fat32, tabla-fat]
calculos:
  - enunciado: 'a) ¿Cuántas entradas tendría la Tabla FAT?'
    campos:
      - { etiqueta: 'Entradas', respuesta: 2097152, unidad: entradas }
    justificacion: |
      La FAT tiene **una entrada por cluster** del disco:

      `8 GiB / 4 KiB = 2^33 / 2^12 = 2^21 = 2.097.152 entradas`

      FAT32 direcciona hasta 2<sup>28</sup> clusters, así que alcanza para todo el disco: la tabla
      usa solo las 2<sup>21</sup> entradas que hacen falta (los clusters que tiene el disco).
  - enunciado: 'b) ¿Qué porcentaje del disco estaría ocupado por la Tabla FAT?'
    campos:
      - { etiqueta: 'Tamaño de la FAT', respuesta: 8, unidad: MiB }
      - {
          etiqueta: 'Porcentaje del disco (exacto, sin redondear)',
          respuesta: 0.09765625,
          unidad: '%',
        }
    justificacion: |
      Cada entrada de FAT32 ocupa **4 bytes** (32 bits):

      `2^21 entradas × 2^2 bytes = 2^23 bytes = 8 MiB`

      Sobre el disco: `2^23 / 2^33 = 2^-10 = 1/1024` → **0,09765625 %** (casi 0,1 %).
  - enunciado: 'c) ¿Cuántos bits de cada entrada se desperdiciaron?'
    campos:
      - { etiqueta: 'Bits desperdiciados', respuesta: 11, unidad: bits }
    justificacion: |
      Para numerar 2<sup>21</sup> clusters alcanzan **21 bits**, y cada entrada ocupa 32:

      `32 − 21 = 11 bits` sin usar en cada entrada.

      De esos 11, **4** los desperdicia siempre el formato (FAT32 solo usa 28 bits para direccionar),
      y los otros **7** se pierden porque este disco tiene menos clusters que los 2<sup>28</sup> que
      FAT32 podría numerar.
---

Si un disco rígido de 8 GiB se formatea con FAT32, usando clusters de 4 KiB, y descartando el espacio
ocupado por la información administrativa del filesystem, se pide:

- a) ¿Cuántas entradas tendría la Tabla FAT?
- b) ¿Qué porcentaje del disco estaría ocupado por la Tabla FAT?
- c) ¿Cuántos bits de cada entrada se desperdiciaron?
