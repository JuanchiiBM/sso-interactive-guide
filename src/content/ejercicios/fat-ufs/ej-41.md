  - enunciado: 'a) Tamaño real del filesystem y tamaño del archivo.'
    campos:
      - { etiqueta: 'FS real', respuesta: 512, unidad: GiB }
      - { etiqueta: 'Tamaño del archivo', respuesta: 7680, unidad: bytes }
    justificacion: |
      **FS:** FAT32 numera 2<sup>28</sup> bloques:
      `2^28 × 2 KiB = 2^28 × 2^11 B = 2^39 B =` **512 GiB**. Es menos que el disco (1 TiB), así que
      el real es el teórico: el resto del disco queda sin direccionar.

      **Archivo:** ocupa 4 bloques, y el último tiene 512 B sin usar (fragmentación interna):

      `4 × 2048 − 512 = 8192 − 512 =` **7680 bytes** (7,5 KiB).
  - enunciado: 'b) Tabla FAT con el único archivo del disco. Escribí `FIN` en el último bloque y `—` en las entradas libres.'
    tabla:
      columnas: [Entrada, Siguiente]
      filas:
        - ['4', { respuesta: 6 }]
        - ['5', { respuesta: '—', texto: true, alternativas: ['-', libre, '0'] }]
        - ['6', { respuesta: 8 }]
        - ['7', { respuesta: '—', texto: true, alternativas: ['-', libre, '0'] }]
        - ['8', { respuesta: 10 }]
        - ['9', { respuesta: '—', texto: true, alternativas: ['-', libre, '0'] }]
        - ['10', { respuesta: FIN, texto: true, alternativas: [EOF] }]
    justificacion: |
      Cada entrada de un bloque del archivo guarda el **número del bloque siguiente**; la del último
      tiene la marca de fin. Cadena: **4 → 6 → 8 → 10 → FIN**.

      El resto de la tabla (incluidas las entradas 5, 7 y 9) queda **libre**: es el único archivo del
      disco. El primer bloque (4) no está en la FAT: lo guarda la **entrada de directorio** del
      archivo.

      Es la misma idea que el ejercicio 35.

Un disco de 1 TiB contiene un volumen FAT32 con bloques de 2 KiB. Existe un único archivo compuesto
por los bloques 4, 6, 8 y 10 (en ese orden).

a) Indique el Tamaño real del File System y el tamaño del archivo sabiendo que genera 512 bytes de
fragmentación interna.

b) ¿Cómo quedaría la tabla FAT teniendo en cuenta el único archivo del disco?
