calculos:
  - enunciado: 'a) ¿Cuántas entradas puede direccionar teóricamente?'
    campos:
      - { etiqueta: 'Entradas', respuesta: 4096, unidad: entradas }
    justificacion: |
      FAT12 usa entradas de **12 bits**: con 12 bits hay 2<sup>12</sup> = **4096** combinaciones, una
      por cluster que se puede numerar.
  - enunciado: 'b) ¿Cuál es el espacio máximo direccionable teórico?'
    campos:
      - { etiqueta: 'Espacio direccionable teórico', respuesta: 16, unidad: MiB }
    justificacion: |
      `2^12 clusters × 4 KiB = 2^12 × 2^12 bytes = 2^24 bytes = 16 MiB`
  - enunciado: 'c) ¿Cuál es el tamaño de puntero en bits y en bytes?'
    campos:
      - { etiqueta: 'En bits', respuesta: 12, unidad: bits }
      - { etiqueta: 'En bytes', respuesta: 1.5, unidad: bytes }
    justificacion: |
      Cada entrada de la FAT es el puntero al cluster siguiente: **12 bits** = 12 / 8 = **1,5 bytes**.

      Por eso la tabla de FAT12 se guarda empaquetando de a dos entradas en 3 bytes. Con 4096
      entradas, la tabla completa ocupa `4096 × 1,5 B = 6 KiB`.
  - enunciado: 'd) Si se duplica el tamaño de cluster, ¿cuál pasa a ser el espacio direccionable teórico?'
    campos:
      - { etiqueta: 'Con clusters de 8 KiB', respuesta: 32, unidad: MiB }
    justificacion: |
      La cantidad de entradas no cambia (sigue siendo FAT12), así que el espacio se **duplica**:

      `2^12 × 8 KiB = 2^12 × 2^13 bytes = 2^25 bytes = 32 MiB`
preguntas:
  - enunciado: 'e) ¿Qué desventaja podría generar ese cambio al almacenar archivos pequeños?'
    opciones:
      - texto: 'La tabla FAT se duplica y ocupa más disco'
        explicacion: 'La tabla tiene las mismas 4096 entradas: no cambia de tamaño.'
      - texto: 'Más fragmentación interna: cada archivo chico ocupa un cluster de 8 KiB entero'
        explicacion: 'Correcta: se pierde hasta casi un cluster por archivo.'
      - texto: 'Más fragmentación externa'
        explicacion: 'FAT puede usar cualquier cluster libre: no necesita huecos contiguos.'
      - texto: 'Los archivos chicos pasan a necesitar más entradas de la FAT'
        explicacion: 'Al contrario: con clusters más grandes, un archivo usa la misma cantidad de clusters o menos.'
    correcta: 1
    justificacion: |
      Un archivo ocupa **clusters enteros**. Con clusters de 8 KiB, un archivo de 1 KiB desperdicia
      7 KiB (antes, 3 KiB). Con muchos archivos chicos, buena parte del disco queda asignada sin datos:
      es **fragmentación interna**.

      Es el intercambio de siempre: cluster más grande = más espacio direccionable con los mismos
      bits, a cambio de perder más en el último cluster de cada archivo.

- d) ¿Qué sucedería con la capacidad de direccionamiento si se duplica el tamaño de cluster?
- e) ¿Qué desventaja podría generar ese cambio al almacenar archivos pequeños?
