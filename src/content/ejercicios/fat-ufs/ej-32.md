      **Libre:** `1024 − (256 + 256) − (128 + 128) − (100 + 100) =` **56 KiB**, en un solo hueco.

      **FAT original:** el disco de 8 MiB tiene `2^23 / 2^7 = 2^16` bloques (justo lo que direcciona
      FAT16). Entradas de 2 B: `2^16 × 2 B = 2^17 B =` **128 KiB**.

      **FAT con 1 KiB:** `8 MiB / 1 KiB = 2^13` bloques → `2^13 × 2 B = 2^14 B =` **16 KiB**.

Un sistema administra su espacio de memoria de usuario de 1 MiB con segmentación pura y almacena sus
archivos bajo un FS FAT16 con bloques de 128 bytes, formateado en un disco de 8 MiB. Actualmente se
ejecutan dos procesos con las siguientes tablas de segmentos:

<div class="codigo-columnas">

**Tabla Segmentos PA**

| Base | Tamaño |
| --- | --- |
| 0 | 256 |
| 768 | 256 |

**Tabla Segmentos PB**

| Base | Tamaño |
| --- | --- |
| 384 | 128 |
| 576 | 128 |

</div>

> Nota: todos los valores están expresados en KiB.

Si se crea exitosamente un nuevo proceso C con dos segmentos de 100 KiB cada uno:

- a) Indique el estado final de las tablas de segmentos y del espacio libre en memoria.

Sabiendo que en este sistema se desea utilizar el espacio de memoria de usuario para cargar también
las estructuras administrativas del FS, el administrador (Luciano) sospecha que el espacio libre que
queda tras el punto a) es insuficiente para alojar la tabla FAT, por lo que propone aumentar el
tamaño de bloques a 1 KiB:

- b) Justifique si la sospecha de Luciano es correcta y si su propuesta cumpliría el objetivo
  indicando el tamaño original de la tabla FAT y cuál sería su tamaño si se aplicara el cambio.
