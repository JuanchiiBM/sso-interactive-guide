calculos:
  - enunciado: 'Previo: datos que se deducen del FS.'
    campos:
      - { etiqueta: 'Tamaño de puntero', respuesta: 32, unidad: bits }
      - { etiqueta: 'Punteros por bloque', respuesta: 256, unidad: punteros }
    justificacion: |
      Espacio teórico del FS = `2^(bits de puntero) × tamaño de bloque`:

      `2^n × 2^10 = 2^42 (4 TiB)` → `n = 32` → punteros de **32 bits** (4 B).

      Punteros por bloque: `1 KiB / 4 B = 2^10 / 2^2 = 2^8 =` **256**.
  - enunciado: 'a) Tamaño máximo de un archivo con este inodo.'
    campos:
      - { etiqueta: 'Archivo máximo (exacto)', respuesta: 16843020, unidad: KiB }
    justificacion: |
      | Punteros | Bloques de datos | Tamaño |
      | --- | --- | --- |
      | 12 directos | 12 | 12 KiB |
      | 1 indirecto simple | 2<sup>8</sup> = 256 | 256 KiB |
      | 1 indirecto doble | (2<sup>8</sup>)<sup>2</sup> = 65.536 | 64 MiB |
      | 1 indirecto triple | (2<sup>8</sup>)<sup>3</sup> = 16.777.216 | 16 GiB |
      | **Total** | **16.843.020** | **16.843.020 KiB ≈ 16 GiB** |

      "Un poco más de 16 GiB": el archivo de **160 GiB no entra** en un inodo, aunque sobre lugar en
      el disco. Ese es el error que encontró Peter.
  - enunciado: 'b) Tamaño máximo del FS (y de un archivo) con FAT32 y bloques de 1 KiB.'
    campos:
      - { etiqueta: 'FS máximo con FAT32', respuesta: 256, unidad: GiB }
    justificacion: |
      FAT32 usa **28 bits** de cada entrada para numerar clusters:

      `2^28 × 2^10 = 2^38 B =` **256 GiB**.

      En FAT el archivo máximo es el FS entero (no hay inodo que lo limite): 256 GiB > 160 GiB.
  - enunciado: 'c) Bloques accedidos para leer el mp3 de 530 KiB (con el FS original).'
    campos:
      - { etiqueta: 'Bloques accedidos', respuesta: 534, unidad: bloques }
    justificacion: |
      530 KiB / 1 KiB = **530 bloques de datos**:

      - 12 por los **directos** → quedan 518.
      - 256 por el **indirecto simple** + 1 bloque de punteros → quedan 262.
      - Por el **indirecto doble**: 1 bloque de punteros de 1.er nivel + 2 de 2.º nivel (256 + 6
        datos) → quedan 0.

      `12 + 256 + 1 + 256 + 2 + 6 + 1 =` **530 BD + 4 BP = 534 bloques**.

    opciones:

      - texto: 'Achicar el bloque a 512 B para tener más bloques'
        explicacion: 'Bloques más chicos dan menos punteros por bloque: el máximo baja.'
    correcta: 1
    justificacion: |
      El problema no es el disco sino el **inodo**: con 12 D + IS + ID + IT direcciona poco más de
      16 GiB. Dos soluciones:

      - **Indirecto cuádruple:** suma `(2^8)^4 × 2^10 = 2^42 = 4 TiB` (todo el FS).
      - **Agrandar el bloque:** crecen el bloque y los punteros por bloque, y el indirecto triple
        rinde mucho más.
  - enunciado: 'b) Con FAT32 (mismo tamaño de bloque), ¿tendría el mismo problema? ¿Aprovecharía los 4 TiB?'
    opciones:

Peter quiere descargar (de forma legal, por supuesto) la nueva película de Disney: "Intensamente 2".
Como es un nerd del cine, decide descargar el archivo en calidad 8K. Este mismo, si bien pesa
160 GiB, entra perfecto en su disco de 4 TiB. No obstante, al descomprimir las diferentes partes
descargadas de la película para obtener el archivo final, se encuentra con un error.

Se sabe que la computadora de Peter utiliza un file system UFS con las siguientes características:

- Cada uno de los inodos posee 12 punteros directos, 1 puntero indirecto simple, 1 puntero
  indirecto doble y un puntero indirecto triple.
- El máximo espacio teórico direccionable del FS es 4 TiB y el tamaño de bloque es de 1 KiB.

Responda:

- a) ¿Con qué problema se encontró Peter al descomprimir el archivo? Mencione y explique un cambio
  en la configuración del file system que resuelva el problema.
- b) En caso de que la computadora de Peter utilizara FAT 32 en lugar de UFS, con el mismo tamaño de
  bloque, ¿se habría encontrado con el mismo problema? ¿Por qué? ¿Podría Peter en este caso
  aprovechar en su totalidad su disco de 4 TiB?
- c) Peter se frustró y al final se fue a escuchar la banda sonora de Shrek 2, la cual tiene
  guardada en un archivo mp3 de 530 KiB. ¿Cuántos accesos a bloques en disco fueron requeridos para
  ello? (con el FS original del enunciado).
