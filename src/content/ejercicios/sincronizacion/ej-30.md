    Un **rendezvous** corredor ↔ terminal, un **productor-consumidor por carrera** (terminal → lista de
    turnos → empleado) y un **aviso por número de ticket**:

    | Semáforo | Tipo | Inicial | Para qué |
    | -------- | ---- | ------- | -------- |
    | `terminalLibre` | mutex | 1 | un corredor a la vez usa la terminal (de escribir a recibir el ticket) |
    | `inputEscrito` | contador | 0 | la terminal espera que haya algo escrito (`leerInput()` falla si no) |
    | `ticketListo` | contador | 0 | el corredor espera que le entreguen el ticket |
    | `mutexTurnos[3]` | mutex por carrera | 1 | cada lista de turnos es compartida |
    | `hayTurnos[3]` | contador por carrera | 0 | el empleado espera números en **su** lista |
    | `llamado[100]` | contador por número | 0 | cada corredor espera que llamen a **su** número |

    - `terminalLibre` se libera recién después de `recibirTicket()`: si se soltara al escribir, otro
      corredor podría pisar el input o llevarse el ticket del primero.
    - `signal(ticketListo)` puede ir antes de agregar el número a la lista: el empleado igual no lo llama
      hasta que `hayTurnos[id]` lo habilita.
    - `llamado` es un array por número: los empleados de carreras distintas llaman en cualquier orden,
      así que cada corredor espera **su** llamado, no el primero que ocurra.
---

Una maratón tiene un sistema de tickets para inscribirse a distintas carreras según la experiencia de cada corredor. Los mismos utilizan **una única terminal** donde escriben en qué carrera quieren inscribirse (hay 3 para elegir); luego de recibir el ticket **esperan a ser llamados por el número** del mismo.

La terminal genera el ticket, agrega su número a la lista de turnos de esa carrera y le entrega el ticket al corredor. Por cada carrera hay un empleado que va tomando números de su lista de turnos para llamarlos a posicionarse.

Sincronice el siguiente pseudocódigo concurrente utilizando semáforos de forma que cumpla con el comportamiento descrito sin generar deadlocks ni starvation.

```c
struct ticket_t {
  idCarrera; // 0 a 2
  número;    // 0 a 99
}
```

<div class="codigo-columnas">

**Corredor (100 instancias)**

```c
acercarseATerminal();
escribirIdCarreraEnInput();
ticket_t ticket = recibirTicket();
posicionarseCarrera();
```

**Terminal de tickets (1 instancia)**

```c
while(true) {
  id = leerInput();
  ticket_t ticket = generarTicket(id);
  entregarTicket();
  agregar(ticket.número, turnos[id]);
}
```

**Empleado (3 instancias)**

```c
while(true) {
  numLlamar = retirar(turnos[getId()]);
  llamarCorredor();
}
```

</div>

**Notas:** la función `leerInput()` falla si no hay nada escrito. La función `generarTicket()` le asigna un número entre 0 y 99 al ticket. El proceso Empleado dispone de una función `getId()` que devuelve el id correspondiente a su carrera.
