nota: |
  **Semáforos y `fork()`**: `fork()` duplica la memoria del proceso, así que una variable común queda
  **copiada** y el hijo no ve los cambios del padre (ni al revés). Los semáforos, en cambio, son
  estructuras **del SO**: en los ejercicios se asume que los semáforos creados antes del `fork()` los
  **comparten** padre e hijo, y un `signal` de uno puede despertar al otro. Por eso sirven para
  sincronizar al padre con sus hijos. Además, a diferencia del mutex, en un semáforo **contador** o de
  sincronización el `wait` y el `signal` los pueden hacer procesos distintos. Y el hijo termina en
  `exit(0)`: lo que tenga que hacer antes de irse va antes de esa línea.
---

Sincronice el siguiente código, correspondiente a un proceso que genera procesos hijos, para evitar inconsistencias, deadlocks e inanición. Además debe tener en cuenta lo siguiente:

- ✓ El archivo donde se escriben los logs es único.
- ✓ No debe haber más de 50 procesos en ejecución.
- ✓ El padre debe escribir en el log antes que el hijo recién creado.

**Proceso A**

```c
int main() {
  while (true) {
    pid = fork();
    if (pid < 0) {
      log('Error');
    } else if (pid == 0) {
      log("Y yo soy el hijo");
      realizarTarea();
      // Finaliza el proceso hijo
      exit(0);
    } else {
      // Padre
      log(pid + " soy tu padre");
    }
  }
}
```
