  justificacion: |
    Dos **productor-consumidor** (Pedro → prompts → agentes y agentes → repositorio → bot) y, al final, un
    **aviso dirigido** del bot al agente dueño del PR:

    | Semáforo | Tipo | Inicial | Para qué |
    | -------- | ---- | ------- | -------- |
    | `mutex_prompts`, `mutex_repositorio`, `mutex_issues` | mutex | 1 | cada lista es compartida |
    | `hay_prompts` | contador | 0 | los agentes esperan un prompt |
    | `hay_prs` | contador | 0 | el bot espera un PR publicado |
    | `sem_issues[10]` | contador por agente | 0 | cada agente espera el issue de **su** PR |

    - El bot avisa con `signal(sem_issues[id_agente(pr)])` y el agente espera con `wait(sem_issues[id()])`:
      las dos puntas usan el mismo índice, el id del agente dueño del PR.
    - Con un solo `sem_issues`, el aviso lo podría consumir cualquier agente que esté esperando, y no
      necesariamente el dueño del PR.
    - `generar_pr` y `corregir_y_mergear_pr` quedan **fuera** de los mutex: cada agente trabaja en
      paralelo y solo se protege el acceso a las listas compartidas.
---

Pedro decidió suscribirse al plan Max de Claudio Code para acelerar el desarrollo de su nuevo proyecto. Para ello, revisa el Figma con los requerimientos del cliente y genera prompts que son procesados por **cualquiera de las 10 instancias** de Agente Claudio Code. Cada instancia toma un prompt de la cola, genera un Pull Request (PR) y lo publica en el repositorio del proyecto.

Pedro integró al repositorio un **Code Quality Bot** que revisa continuamente los PRs y publica issues asociados a los problemas encontrados. Luego de que el issue asociado al PR es generado, **la instancia de Agente Claudio Code responsable de este** debe tomar dicho issue, realizar las correcciones necesarias y actualizar el PR antes de mergear al repositorio.

Sincronice el siguiente pseudocódigo concurrente utilizando semáforos y sin generar deadlocks ni starvation.

Variables compartidas: `prompts`, `issues` y `repositorio`

<div class="codigo-columnas">

**Pedro**

```c
while(1) {
  revisar_figma();
  prompt = generar_prompt();
  agregar_prompt(prompts, prompt);
}
```

**Agente Claudio Code (10 instancias)**

```c
while(1) {
  prompt = obtener_prompt(prompts);
  pr = generar_pr(prompt);
  pushear_cambios(repositorio, pr);
  issue = obtenerIssue(issues);
  corregir_y_mergear_pr(pr, issue);
}
```

**Code Quality Bot (1 instancia)**

```c
while(1) {
  pr = obtener_pr(repositorio);
  issue = revisar_codigo(pr);
  postear_issue(issues, issue);
}
```

</div>

Las instancias de Agente Claudio Code poseen una función `id()` que devuelve el identificador de sí misma (valores entre 0 y 9). El Code Quality Bot posee una función `id_agente(pr)` que devuelve el id del agente que creó el PR recibido por parámetro.
