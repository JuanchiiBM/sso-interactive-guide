  - tipo: secuencia
    acciones:
    - print("C")

    - print("A")
    - print("D")
    - print("A")
    - print(" CAMPEON")
    nombre: Se imprime la secuencia pedida, en orden, para siempre
  - tipo: sin-deadlock
  solucion: |
    semaphore sC = 1, sA = 0, sN = 0, sD = 0, sCAMP = 0, finA = 0;

    void A() {
      while(1){
        wait(sA);
        print("A");
        signal(finA);
      }
    }

    void C() {
      while(1){
        wait(sC);
        print("C");
        signal(sA);
        wait(finA);
        signal(sN);
      }
    }

    void N() {
      while(1){
        wait(sN);
        print("N");
        signal(sA);
        wait(finA);
        signal(sD);
      }
    }

    void D() {
      while(1){
        wait(sD);
        print("D");
        signal(sA);
        wait(finA);
        signal(sCAMP);
      }
    }

    void CAMPEON() {
      while(1){
        wait(sCAMP);
        print(" CAMPEON");
        signal(sC);
      }
    }
  justificacion: |
    La dificultad es la **A**: aparece tres veces (C**A**N**A**D**A**) y su código es el mismo en cada vuelta,
    así que A **no puede saber** quién sigue. La salida: A solo avisa "terminé" (`finA`) y **quien la
    habilitó decide quién sigue**:

    - C imprime, habilita a A, espera `finA` y habilita a N.
    - N imprime, habilita a A, espera `finA` y habilita a D.
    - D imprime, habilita a A, espera `finA` y habilita a CAMPEON.
    - CAMPEON imprime y vuelve a habilitar a C.

    Solo `sC` arranca en 1 (la frase empieza con C).

    ⚠️ Una trampa típica es que **A haga los `signal` de todos** (`signal(sC)`, `signal(sN)`, …) y que cada
    letra "cuente" con `wait(...)x3`: como A deja habilitada a C en cada vuelta, después de "CA" C puede
    volver a imprimir antes que N. Los tests lo encuentran: probá esa versión.
