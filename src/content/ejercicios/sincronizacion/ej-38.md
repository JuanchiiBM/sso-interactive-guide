  opciones:
  - texto: 'Sí: un Procesador retiene `mutex_imagenes` esperando `imagenes_contador`, y el Generador queda esperando el mutex para agregar la imagen'
    explicacion: 'El Generador no hace ningún wait: no pide el mutex, así que siempre llega a su signal(imagenes_contador).'
  - texto: 'No: hay espera con el mutex tomado, pero no circular, porque el que la destraba (el Generador) nunca se bloquea'
    explicacion: 'Correcta: el único que retiene y espera es el Procesador, y lo que espera lo produce alguien que no espera nada.'
  - texto: 'Sí: `mutex_status` no está inicializado y los Confirmadores se bloquean en él'
    explicacion: 'Es un error a corregir en b), pero ningún otro proceso lo retiene: no forma una espera circular con nadie.'
  - texto: 'No: con un único mutex en el código nunca puede haber espera circular'
    explicacion: 'Hay dos mutex (mutex_imagenes y mutex_status), y la razón no es la cantidad: también hay espera circular con contadores.'
  correcta: 1
  justificacion: |
    **No hay deadlock.** Para que haya deadlock tienen que darse las cuatro condiciones; la que falla
    es la **espera circular**:

    | Condición | ¿Se da? |
    | --- | --- |
    | Exclusión mutua | Sí: `mutex_imagenes` (y `mutex_status`) |
    | Retención y espera | Solo el **Procesador**: tiene `mutex_imagenes` y espera `imagenes_contador` |
    | Sin desalojo | Sí: un semáforo no se le quita a quien lo tomó |
    | Espera circular | **No** |

    - `imagenes_contador` lo incrementa el **Generador**, que no hace ningún `wait`: nunca se bloquea,
      así que tarde o temprano hace `signal(imagenes_contador)` y el Procesador sigue. Nadie espera algo
      que tenga el Procesador mientras el Procesador espera algo de él.
    - Los **otros Procesadores** quedan esperando `mutex_imagenes` mientras el primero espera el
      contador: es una **espera innecesaria**, no un deadlock (el que tiene el mutex va a avanzar).
    - Los **Confirmadores** solo usan `mutex_status`, que no pide nadie más (si no se inicializa,
      quedan bloqueados, pero eso es un error de inicialización, no una espera circular).

    Que no haya deadlock no significa que esté bien: en b) se corrigen la capacidad, las condiciones
    de carrera y las esperas innecesarias.

Dado los siguientes procesos cuya tarea es generar y subir una serie de imágenes, sabiendo que "imagenes_list" es una lista compartida y tiene una capacidad máxima de 20 imágenes:

<div class="codigo-columnas">

**Generador (N instancias)**

```c
while(true) {
  generar_imagen(imagenes_list)
  signal(imagenes_contador)
}
```

**Procesador**

```c
while(true) {
  wait(mutex_imagenes)
  wait(imagenes_contador)
  imagen = get_first(imagenes_list)
  subir_archivo(imagen)
  signal(mutex_imagenes)
  signal(confirmaciones)
}
```

**Confirmador (N instancias)**

```c
while(true) {
  wait(confirmaciones)
  img = leer_ultimo(imagenes_list)
  wait(mutex_status)
  if(img.status = 0)
    print("Error al subir la imagen")
  signal(mutex_status)
}
```
