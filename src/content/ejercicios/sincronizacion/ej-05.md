semaforos:
- procesos:
  - nombre: De Paul
    instancias: 1
    codigo: |
      while(TRUE){
        agarra_pelota();
        se_la_paso_messi();
      }
  - nombre: Messi
    instancias: 1
    codigo: |
      while(TRUE){
        recibe_pelota();
        patea_al_arco();
      }
  acciones:
    agarra_pelota(): {}
    se_la_paso_messi():
      efecto:
        pelotas: 1
    recibe_pelota():
      efecto:
        pelotas: -1
    patea_al_arco(): {}
  variables:
    pelotas: 0
  tests:
  - tipo: rango
    variable: pelotas
    min: 0
    nombre: Messi solo recibe pelotas que De Paul le pasó
    motivo: "Hay una intercalación en la que Messi recibe una pelota que De Paul todavía no le pasó."
  - tipo: sin-deadlock
  - tipo: todas-ejecutan
  solucion: |
    semaphore pelota = 0;

    void De_Paul() {
      while(TRUE){
        agarra_pelota();
        se_la_paso_messi();
        signal(pelota);
      }
    }

    void Messi() {
      while(TRUE){
        wait(pelota);
        recibe_pelota();
        patea_al_arco();
      }
    }
  justificacion: |
    Es una **sincronización de orden**: `recibe_pelota()` tiene que ocurrir después de
    `se_la_paso_messi()`. Se usa un semáforo inicializado en **0** (regla de la cátedra: los de
    sincronización de tareas arrancan en 0): Messi hace `wait` y queda bloqueado hasta que De Paul hace
    `signal` al pasarla.

    - Tipo: **contador** usado para sincronizar (cuenta pelotas pasadas y no recibidas).
    - Si además se quisiera que De Paul no agarre otra pelota hasta que Messi reciba la anterior, se
      agrega un segundo semáforo en sentido contrario (inicializado en 1 en De Paul).
